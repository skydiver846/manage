## 0단계 (수업 전): 행정망에서 되는지 먼저 확인

강의장은 **행정망**입니다. GitHub·Vercel은 리허설에서 확인됐지만, Firebase는 출석부가 장부에 접속하는 주소(`firestore.googleapis.com`)와 프로그램 주소(`gstatic.com`)가 따로 있어서 **화면은 열리는데 저장만 안 되는** 경우가 생길 수 있습니다.

1. 강사가 1~4단계를 미리 해 두고 Firebase 설정값을 받아 둡니다 (강사 노트북, 아무 망이나)
2. 강의장 PC에서 **접속 점검 페이지**(`prototype-demo/network-check.html`)를 열고, 2단계에 설정값을 붙여넣어 **[Firebase 연결 시험]**
3. 결과에 따라 진행 방식을 정합니다

| 점검 결과 | 진행 방식 |
|---|---|
| **성공** | **A안: 수강생 실습.** 아래 1~7단계를 그대로 진행 |
| **실패** | **B안: 강사 시연.** 아래 진행표대로 |

> 🧑‍🏫 B안에서 꼭 보여 줄 장면: 같은 출석부 주소를 **행정망 PC**에서 열면 "연결 안 됨", **휴대폰(LTE)** 에서 열면 출석이 됩니다. **망분리**를 눈으로 이해하는 순간이고, "그래서 기관 업무용 서비스는 다르게 만들어야 한다"로 이어집니다.

### 실제 기관 서비스로 만들 때 (마무리 멘트)

- 이번 실습은 **예시 이름만** 쓰는 연습입니다. 실제 교육생 이름 같은 **개인정보를 해외 클라우드에 저장**하려면 기관의 개인정보·클라우드 규정 검토가 필요합니다.
- 공공기관이 외부 클라우드를 업무에 쓰려면 **클라우드 보안인증(CSAP)** 등 기관 기준을 따라야 합니다. 정식 서비스는 인증된 클라우드나 기관 내부 서버로 만드는 것이 일반적입니다 (`firebase 연동 가이드.md` 0장 참고).
- 수업에서 배운 흐름(PRD → 화면 → 장부 규칙 → 배포)은 어떤 클라우드를 쓰든 똑같이 적용됩니다.

지난 회차의 출석부는 **화면은 공유되지만 장부는 각자의 브라우저에** 있었습니다. 오늘은 모두가 함께 쓰는 장부(데이터베이스)를 붙여 **짝꿍 휴대폰에서도 같은 명단**이 보이게 합니다. 모든 작업은 **파란 "업무" Chrome 프로필 창**에서 합니다.

```
 지난 회차:  [내 휴대폰 서랍]   [짝꿍 휴대폰 서랍]      ← 따로따로
 오늘:      [내 휴대폰] ─┐
            [짝꿍 휴대폰] ┼──▶  Firebase (공용 장부)   ← 모두가 같은 명단
            [교관 PC]   ─┘
```

## 2단계: 공용 장부(Firestore) 만들기 (5분)

1. 왼쪽 메뉴 **빌드(Build)** → **Firestore Database** → **[데이터베이스 만들기]**
2. 에디션 선택이 나오면 **Standard**
3. **위치: `asia-northeast3 (서울)`** → ⚠️ 나중에 바꿀 수 없습니다
4. **프로덕션 모드**로 시작 → **[만들기]**

> 🧑‍🏫 "프로덕션 모드는 처음에 **아무도 장부를 못 쓰게 잠근** 상태입니다. 다음 단계에서 우리가 정한 규칙대로만 열어 줍니다."
> **테스트 모드**를 고르면 당장은 편하지만 **30일 뒤 자동으로 잠겨** 출석부가 갑자기 멈춥니다. 그리고 그동안 누구나 장부를 지울 수 있습니다. 가이드와 같은 이유로 프로덕션 모드 + 규칙 붙여넣기를 권합니다.

## 3단계: 장부 사용 규칙 정하기 (10분)

Firestore 화면 위쪽 **규칙(Rules)** 탭 → 내용을 모두 지우고 아래를 붙여넣기 → **[게시(Publish)]**

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /attendance/{recordId} {
      // 명단은 누구나 볼 수 있다
      allow read: if true;
      // 새 출석은 정해진 칸만, 정해진 모양으로 쓸 수 있다
      allow create: if request.resource.data.keys().hasOnly(['name', 'no', 'date', 'time'])
        && request.resource.data.keys().hasAll(['name', 'no', 'date', 'time'])
        && request.resource.data.name is string
        && request.resource.data.name.size() > 0
        && request.resource.data.name.size() <= 20
        && request.resource.data.no is string
        && request.resource.data.no.matches('^[0-9]{2}$');
      // 한번 쓴 출석은 고치거나 지울 수 없다
      allow update, delete: if false;
    }
  }
}
```

> 🧑‍🏫 규칙을 **PRD 말로** 읽어 주세요.
> - "명단은 누구나 본다" → `allow read`
> - "이름·번호·날짜·시각 네 칸을 모두, 이것만 쓴다. 이름은 20자 이내, 번호는 숫자 2자리" → `allow create`
> - "한번 쓴 출석은 고치거나 지울 수 없다" → `allow update, delete: if false`
>
> 마지막 줄 덕분에 **중복 출석도 장부가 막아 줍니다.** 출석 한 건의 이름표(문서 ID)를 `날짜_번호_이름` 으로 정하면, 같은 날 같은 사람이 다시 쓰려는 것은 "고치기"가 되어 거절됩니다.
>
> ⚠️ 이 규칙은 **실습용**입니다. 누구나 아무 이름으로 출석할 수 있습니다(PRD에서 로그인은 범위 밖). 실제 서비스는 로그인(Authentication)과 역할별 규칙이 필요합니다(`firebase 연동 가이드.md` 3·5장).

## 4단계: 출석부와 장부를 잇는 설정값 받기 (5분)

1. 왼쪽 위 **프로젝트 개요** → 가운데 **`</>` (웹)** 아이콘
2. 앱 닉네임 `출석부` → **Firebase Hosting 체크하지 않기** (배포는 Vercel이 함) → **[앱 등록]**
3. 화면에 나오는 코드 중 **`const firebaseConfig = { ... };`** 부분만 복사 → 옵시디언 `02_참고자료` 에 `Firebase 설정값` 노트로 저장
4. **[콘솔로 이동]**

```js
const firebaseConfig = {
  apiKey: "AIza…",
  authDomain: "attendance-12-a1b2c.firebaseapp.com",
  projectId: "attendance-12-a1b2c",
  …
};
```

> 🧑‍🏫 "`apiKey` 라는 이름 때문에 비밀번호 같지만, **웹 앱 설정값은 비밀이 아닙니다.** 화면 코드에 그대로 들어가 누구나 볼 수 있어요. 장부를 지키는 것은 3단계의 **규칙**입니다." (`firebase 연동 가이드.md` 2.1절과 같은 설명)
> 나중에 다시 찾을 때: **⚙ 프로젝트 설정 → 일반 → 내 앱 → SDK 설정 및 구성 → 구성(Config)**

## 5단계: PRD 고치기 → Claude로 코드 고치기 (15분)

**① PRD를 먼저 고칩니다** (기준 문서는 언제나 PRD). 옵시디언에서 PRD를 **v0.4** 로:
- 6번 범위 밖에서 **"여러 기기 간 데이터 공유"를 삭제** → 이제 범위 안
- 4번 핵심 기능에 **"모든 기기에서 같은 명단을 실시간으로 본다"** 추가
- **삭제(×)와 전체 초기화는 범위 밖으로** 이동 (장부 규칙상 지울 수 없음, 관리자 기능은 다음 단계)

**② Claude 새 채팅**에 **PRD v0.4 + 현재 `index.html`** 두 파일을 첨부하고:

```
첨부한 index.html은 출석 기록을 브라우저(localStorage)에 저장하는 출석부야.
첨부한 PRD v0.4에 맞게, 기록을 Firebase Firestore에 저장하도록 고쳐 줘.

- 내 Firebase 설정값은 아래와 같아:
  (여기에 firebaseConfig 붙여넣기)
- HTML 파일 하나로 유지하고, Firebase는 공식 CDN(gstatic.com)의 모듈 방식으로 불러와 줘
- 컬렉션 이름은 attendance, 필드는 name, no, date(YYYY-MM-DD), time(HH:MM)만 써 줘
- 문서 ID는 "날짜_번호_이름"으로 정하고, 같은 문서가 이미 있으면 "이미 출석했습니다"를 보여 줘
- 오늘 날짜 기록만 실시간으로 보여 줘 (정렬은 화면에서 해 줘)

- 나머지 화면 디자인과 정시/지각 판정은 그대로 둬
```

> 🧑‍🏫 이 지시문은 모듈 3의 **맥락 + 조건**을 그대로 쓴 것입니다. 특히 "필드는 이것만", "문서 ID는 이렇게"가 3단계 규칙과 **정확히 맞아야** 출석이 저장됩니다. 규칙과 코드가 어긋나면 출석 버튼을 눌러도 아무 일도 안 일어납니다.
> "정렬은 화면에서" 조건이 없으면, 날짜로 거르고 시각으로 정렬하는 조회에 **색인(index)을 만들라는 오류**가 날 수 있습니다.

**③ 내 컴퓨터에서 먼저 확인**: Claude 결과를 메모장에 `index.html`(UTF-8)로 저장 → 더블클릭 → 출석 체크 → Firebase 콘솔 **Firestore → 데이터** 탭에 `attendance` 아래 기록이 생기면 성공

## 6단계: GitHub에 커밋 → 자동 배포 (5분)

1. GitHub `attendance-prototype` → `index.html` → **연필(✏️)**
2. 기존 내용을 **Ctrl + A** 로 모두 선택 → 새 코드로 **붙여넣기**
3. **[Commit changes…]** → 메시지 `출석 기록을 Firebase 공용 장부에 저장` → **[Commit changes]**
4. Vercel **Deployments** 에서 Ready 확인 (주소는 그대로)

> ⭐ **Pro 트랙 (선택)**: 5~6단계를 Claude Code에 맡길 수 있습니다. 저장소를 연결하고 "PRD v0.4에 맞게 index.html을 Firestore에 저장하도록 고치고 커밋해 줘"(5단계 지시문 그대로)라고 지시하면, 복사·붙여넣기 없이 커밋까지 됩니다. 단, Firebase 설정값과 보안 규칙은 사람이 직접 확인합니다. 방법은 모듈 10 참고.

## 7단계: 짝꿍과 같은 명단 확인 (5분)

1. 짝꿍과 **같은 출석부 주소**(한 사람의 Domains 주소 QR)를 각자 휴대폰으로 열기
2. 한 사람이 출석 → **다른 사람 화면에 새로고침 없이** 이름이 나타나는지 확인
3. 같은 이름 + 같은 번호로 다시 출석 → "이미 출석했습니다"
4. 강사 PC에서 Firebase 콘솔 **데이터** 탭을 띄워 기록이 쌓이는 모습 보여 주기

```
 지난 회차: 짝꿍 휴대폰에 내 이름 ✗
 오늘:      짝꿍 휴대폰에 내 이름 ✓  (공용 장부)
```

2. GitHub `index.html` 에 붙여넣고 커밋 → 자동 배포

완성본은 3단계 규칙과 그대로 맞물리도록 만들었고, Firestore 에뮬레이터와 브라우저 두 개로 실시간 공유·중복 차단·동명이인 출석까지 시험했습니다. 실제 Firebase 프로젝트에서는 아직 시험하지 않았으니 강의 전에 한 번 확인하세요. 자세한 내용은 `prototype-demo/firebase/README.md`.

> 🧑‍🏫 수업 활용: Claude 결과와 완성본을 나란히 띄워 "칸 이름이 규칙과 같은가?", "문서 ID를 어떻게 정했나?"를 비교하면 좋은 복습이 됩니다.

## 자주 막히는 곳

| 상황 | 해결 |
|---|---|
| 결제 정보·Blaze 업그레이드 안내 | 누르지 않기. Spark(무료)로 충분 |
| 출석 버튼을 눌러도 아무 일 없음 | Chrome **F12 → Console** 에 `permission-denied` 가 보이면 **규칙과 코드의 필드 이름이 다른 것**. 코드가 `name, no, date, time` 만 쓰는지 Claude에게 확인 요청 |
| "The query requires an index" 오류 | 정렬을 화면에서 하도록 Claude에게 다시 요청 (또는 오류 메시지의 링크로 색인 생성) |
| 위치를 잘못 골랐음 | 바꿀 수 없음. 실습용이면 그대로 진행하거나 프로젝트를 새로 만들기 |
| 30일 뒤 출석부가 멈춤 | 테스트 모드로 만든 경우. 3단계 규칙으로 교체 |
| 기록을 지우고 싶음 | 화면에서는 못 지움(규칙). 강사가 Firebase 콘솔 데이터 탭에서 삭제 |

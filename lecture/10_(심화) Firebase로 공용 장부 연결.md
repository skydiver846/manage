## 0단계 (수업 전): 행정망에서 되는지 먼저 확인

강의장은 **행정망**입니다. GitHub·Vercel은 리허설에서 확인됐지만, Firebase는 화면이 장부에 접속하는 주소(`firestore.googleapis.com`)와 프로그램 주소(`gstatic.com`)가 따로 있어서 **화면은 열리는데 저장만 안 되는** 경우가 생길 수 있습니다.

1. 강사가 1~4단계를 미리 해 두고 Firebase 설정값을 받아 둡니다 (강사 노트북, 아무 망이나)
2. 강의장 PC에서 **접속 점검 페이지**(`prototype-demo/network-check.html`)를 열고, 2단계에 설정값을 붙여넣어 **[Firebase 연결 시험]**
3. 결과에 따라 진행 방식을 정합니다

| 점검 결과 | 진행 방식 |
|---|---|
| **성공** | **A안: 교육생 실습.** 아래 1~7단계를 그대로 진행 |
| **실패** | **B안: 강사 시연.** 아래 진행표대로 |

### B안: 강사 시연 진행표

| 단계 | 누가 | 어떻게 |
|---|---|---|
| 1~4 Firebase 설정 | 강사 | 강사 노트북을 **휴대폰 핫스팟**에 연결해 화면 공유로 시연. 교육생은 따라 하지 않고 지켜봄 |
| 5 PRD·코드 고치기 | 교육생 + 강사 | 교육생은 PRD v0.4 고치기와 Claude 지시문 작성까지 (Claude가 열리면). 코드 반영은 강사가 |
| 6 커밋 → 배포 | 강사 | 강사 GitHub 저장소에 커밋 → Vercel 자동 배포 |
| 7 같은 결과표 확인 | 교육생 | 강사 강의평가 주소를 **QR로 띄우고**, 교육생은 **본인 휴대폰(LTE)** 으로 평가 제출 → 강사 화면 결과표에 실시간으로 쌓이는 것 확인 |

> 🧑‍🏫 B안에서 꼭 보여 줄 장면: 같은 강의평가 주소를 **행정망 PC**에서 열면 "연결 안 됨", **휴대폰(LTE)** 에서 열면 평가가 저장됩니다. **망분리**를 눈으로 이해하는 순간이고, "그래서 기관 업무용 서비스는 다르게 만들어야 한다"로 이어집니다.

### 실제 기관 서비스로 만들 때 (마무리 멘트)

- 이번 실습은 **예시 과목·교관**으로 하는 연습입니다. 평가는 익명이지만, 교관 이름과 평가 결과도 **내부 인사·평가 정보**라서 해외 클라우드에 실제 자료를 저장하려면 기관의 개인정보·클라우드 규정 검토가 필요합니다.
- 공공기관이 외부 클라우드를 업무에 쓰려면 **클라우드 보안인증(CSAP)** 등 기관 기준을 따라야 합니다. 정식 서비스는 인증된 클라우드나 기관 내부 서버로 만드는 것이 일반적입니다 (`firebase 연동 가이드.md` 0장 참고).
- 수업에서 배운 흐름(PRD → 화면 → 장부 규칙 → 배포)은 어떤 클라우드를 쓰든 똑같이 적용됩니다.

지난 회차의 강의평가 화면은 **화면은 공유되지만 장부는 각자의 브라우저에** 있었습니다. 오늘은 모두가 함께 쓰는 장부(데이터베이스)를 붙여 **40명이 낸 평가가 한 결과표에 모이게** 합니다. 모든 작업은 **파란 "업무" Chrome 프로필 창**에서 합니다.

```
 지난 회차:  [내 휴대폰 서랍]   [짝꿍 휴대폰 서랍]      ← 따로따로
 오늘:      [내 휴대폰] ─┐
            [짝꿍 휴대폰] ┼──▶  Firebase (공용 장부)   ← 모두가 같은 결과표
            [담당자 PC] ─┘
```

## 수업 전에 강사가 확인할 것

- **행정망 접속**: 0단계 접속 점검으로 A안·B안을 정합니다.
- **기관 규정**: 업무에 외부 클라우드를 쓰려면 기관의 클라우드·개인정보 규정을 먼저 확인합니다(`firebase 연동 가이드.md` 0장). 오늘 실습에는 **예시 과목·교관**만 넣고, 실제 평가 자료는 넣지 않는다고 분명히 말합니다.
- **무료 요금제(Spark)** 로 진행합니다. 결제 정보 입력이나 **Blaze 업그레이드** 안내는 누르지 않게 합니다.

1. 왼쪽 메뉴 **빌드(Build)** → **Firestore Database** → **[데이터베이스 만들기]**
2. 에디션 선택이 나오면 **Standard**

4. **프로덕션 모드**로 시작 → **[만들기]**

> 🧑‍🏫 "프로덕션 모드는 처음에 **아무도 장부를 못 쓰게 잠근** 상태입니다. 다음 단계에서 우리가 정한 규칙대로만 열어 줍니다."
> **테스트 모드**를 고르면 당장은 편하지만 **30일 뒤 자동으로 잠겨** 평가 화면이 갑자기 멈춥니다. 그리고 그동안 누구나 장부를 지울 수 있습니다. 가이드와 같은 이유로 프로덕션 모드 + 규칙 붙여넣기를 권합니다.

## 3단계: 장부 사용 규칙 정하기 (10분)

Firestore 화면 위쪽 **규칙(Rules)** 탭 → 내용을 모두 지우고 아래를 붙여넣기 → **[게시(Publish)]**

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /evaluations/{evalId} {
      // 결과는 누구나 볼 수 있다 (익명 평가라 이름이 없다)
      allow read: if true;
      // 새 평가는 정해진 칸만, 정해진 모양으로 쓸 수 있다
      allow create: if request.resource.data.keys().hasOnly(['subject', 'instructor', 'score', 'date'])
        && request.resource.data.keys().hasAll(['subject', 'instructor', 'score', 'date'])
        && request.resource.data.subject is string
        && request.resource.data.subject.size() > 0
        && request.resource.data.subject.size() <= 30
        && request.resource.data.instructor is string
        && request.resource.data.instructor.size() > 0
        && request.resource.data.instructor.size() <= 20
        && request.resource.data.score is int
        && request.resource.data.score >= 1
        && request.resource.data.score <= 5
        && request.resource.data.date is string
        && request.resource.data.date.matches('^[0-9]{4}-[0-9]{2}-[0-9]{2}$');
      // 한번 낸 평가는 고치거나 지울 수 없다 (지우기는 담당자가 콘솔에서)
      allow update, delete: if false;
    }
  }
}
```

> 🧑‍🏫 규칙을 **PRD 말로** 읽어 주세요.
> - "결과는 누구나 본다" → `allow read`
> - "과목·교관·점수·날짜 네 칸을 모두, 이것만 쓴다. 과목은 30자, 교관은 20자 이내, 점수는 1~5 정수" → `allow create`
> - "한번 낸 평가는 고치거나 지울 수 없다" → `allow update, delete: if false`
>
> **이름 칸이 없다**는 점도 짚어 주세요. 규칙이 `hasOnly` 로 네 칸만 허용하므로, 누가 코드를 고쳐 이름을 넣으려 해도 장부가 거절합니다. **익명 평가를 장부가 지켜 주는** 셈입니다.
> 점수 검사는 화면(JavaScript)에서도 하지만, 화면은 누구나 고칠 수 있습니다. **마지막 문지기는 장부 규칙**입니다.
>
> ⚠️ 이 규칙은 **실습용**입니다. 로그인이 없으니 한 사람이 여러 번 낼 수도 있습니다(PRD에서 로그인은 범위 밖). 실제 서비스는 로그인(Authentication)과 역할별 규칙이 필요합니다(`firebase 연동 가이드.md` 3·5장).

## 4단계: 화면과 장부를 잇는 설정값 받기 (5분)

1. 왼쪽 위 **프로젝트 개요** → 가운데 **`</>` (웹)** 아이콘
2. 앱 닉네임 `강의평가` → **Firebase Hosting 체크하지 않기** (배포는 Vercel이 함) → **[앱 등록]**
3. 화면에 나오는 코드 중 **`const firebaseConfig = { ... };`** 부분만 복사 → 옵시디언 `02_참고자료` 에 `Firebase 설정값` 노트로 저장
4. **[콘솔로 이동]**

```js
const firebaseConfig = {
  apiKey: "AIza…",
  authDomain: "lecture-eval-12-a1b2c.firebaseapp.com",
  projectId: "lecture-eval-12-a1b2c",
  …
};
```

> 🧑‍🏫 "`apiKey` 라는 이름 때문에 비밀번호 같지만, **웹 앱 설정값은 비밀이 아닙니다.** 화면 코드에 그대로 들어가 누구나 볼 수 있어요. 장부를 지키는 것은 3단계의 **규칙**입니다." (`firebase 연동 가이드.md` 2.1절과 같은 설명)
> 나중에 다시 찾을 때: **⚙ 프로젝트 설정 → 일반 → 내 앱 → SDK 설정 및 구성 → 구성(Config)**

## 5단계: PRD 고치기 → Claude로 코드 고치기 (15분)

**① PRD를 먼저 고칩니다** (기준 문서는 언제나 PRD). 옵시디언에서 PRD를 **v0.4** 로:
- 6번 범위 밖에서 **"여러 기기 간 데이터 공유"를 삭제** → 이제 범위 안
- 4번 핵심 기능에 **"모든 기기에서 같은 결과표를 실시간으로 본다"** 추가
- **마지막 응답 취소와 전체 초기화는 범위 밖으로** 이동 (장부 규칙상 지울 수 없음, 관리자 기능은 다음 단계)

**② Claude 새 채팅**에 **PRD v0.4 + 현재 `index.html`** 두 파일을 첨부하고:

```
첨부한 index.html은 강의평가를 브라우저(localStorage)에 저장하는 집계 화면이야.
첨부한 PRD v0.4에 맞게, 평가를 Firebase Firestore에 저장하도록 고쳐 줘.

- 내 Firebase 설정값은 아래와 같아:
  (여기에 firebaseConfig 붙여넣기)
- HTML 파일 하나로 유지하고, Firebase는 공식 CDN(gstatic.com)의 모듈 방식으로 불러와 줘
- 컬렉션 이름은 evaluations, 필드는 subject, instructor, score(1~5 정수), date(YYYY-MM-DD)만 써 줘
- 문서 ID는 Firestore가 자동으로 만들게 해 줘 (addDoc)
- 모든 평가를 실시간으로 받아서 과목·교관별 집계는 화면에서 해 줘
- 마지막 응답 취소, 전체 초기화, 예시 데이터는 없애 줘

```

> 🧑‍🏫 이 지시문은 모듈 3의 **맥락 + 조건**을 그대로 쓴 것입니다. 특히 "필드는 이것만", "score는 정수"가 3단계 규칙과 **정확히 맞아야** 평가가 저장됩니다. 규칙과 코드가 어긋나면 제출 버튼을 눌러도 아무 일도 안 일어납니다. (점수를 `"4"` 같은 **글자**로 저장하는 코드가 흔한 실수입니다. 규칙의 `score is int` 가 거절합니다.)
> "집계는 화면에서" 조건이 없으면, 장부 쪽에서 묶고 정렬하려다 **색인(index)을 만들라는 오류**가 날 수 있습니다.

**③ 내 컴퓨터에서 먼저 확인**: Claude 결과를 메모장에 `index.html`(UTF-8)로 저장 → 더블클릭 → 평가 제출 → Firebase 콘솔 **Firestore → 데이터** 탭에 `evaluations` 아래 기록이 생기면 성공

## 6단계: GitHub에 커밋 → 자동 배포 (5분)

1. GitHub `lecture-eval` → `index.html` → **연필(✏️)**
2. 기존 내용을 **Ctrl + A** 로 모두 선택 → 새 코드로 **붙여넣기**
3. **[Commit changes…]** → 메시지 `강의평가를 Firebase 공용 장부에 저장` → **[Commit changes]**
4. Vercel **Deployments** 에서 Ready 확인 (주소는 그대로)

> ⭐ **Pro 트랙 (선택)**: 5~6단계를 Claude Code에 맡길 수 있습니다. 저장소를 연결하고 "PRD v0.4에 맞게 index.html을 Firestore에 저장하도록 고치고 커밋해 줘"(5단계 지시문 그대로)라고 지시하면, 복사·붙여넣기 없이 커밋까지 됩니다. 단, Firebase 설정값과 보안 규칙은 사람이 직접 확인합니다. 방법은 모듈 11 참고.

## 7단계: 짝꿍과 같은 결과표 확인 (5분)

1. 짝꿍과 **같은 강의평가 주소**(한 사람의 Domains 주소 QR)를 각자 휴대폰으로 열기
2. 한 사람이 평가 제출 → **다른 사람 화면에 새로고침 없이** 응답 수와 평균이 바뀌는지 확인
3. 같은 과목에 **다른 교관** 이름으로 내 보기 → 결과표에 **줄이 따로** 생기는지 확인
4. 강사 PC에서 Firebase 콘솔 **데이터** 탭을 띄워 평가가 쌓이는 모습 보여 주기 (이름 칸이 없는 것도 확인)

```
 지난 회차: 짝꿍 휴대폰 결과표에 내 평가 ✗
 오늘:      짝꿍 휴대폰 결과표에 내 평가 ✓  (공용 장부)
```

## 🛟 막혔을 때: 완성본으로 바꾸기

Claude가 만든 코드가 동작하지 않으면 **완성본**을 씁니다: 저장소 `prototype-demo/firebase/index.html`

1. 완성본의 `firebaseConfig` 부분(▼▼▼ 표시)만 내 설정값으로 바꾸기
2. GitHub `index.html` 에 붙여넣고 커밋 → 자동 배포

완성본은 3단계 규칙과 그대로 맞물리도록 만들었고, Firestore 에뮬레이터와 브라우저 두 개로 실시간 공유·교관별 분리 집계·규칙 위반 거절(14가지)까지 시험했습니다. 실제 Firebase 프로젝트에서는 아직 시험하지 않았으니 강의 전에 한 번 확인하세요. 자세한 내용은 `prototype-demo/firebase/README.md`.

> 🧑‍🏫 수업 활용: Claude 결과와 완성본을 나란히 띄워 "칸 이름이 규칙과 같은가?", "점수를 숫자로 저장했나?"를 비교하면 좋은 복습이 됩니다.

## 자주 막히는 곳

| 상황 | 해결 |
|---|---|
| 결제 정보·Blaze 업그레이드 안내 | 누르지 않기. Spark(무료)로 충분 |
| 제출 버튼을 눌러도 아무 일 없음 | Chrome **F12 → Console** 에 `permission-denied` 가 보이면 **규칙과 코드의 칸이 다른 것**. 코드가 `subject, instructor, score, date` 만 쓰는지, score를 **숫자**로 저장하는지 Claude에게 확인 요청 |
| "The query requires an index" 오류 | 집계·정렬을 화면에서 하도록 Claude에게 다시 요청 (또는 오류 메시지의 링크로 색인 생성) |
| 위치를 잘못 골랐음 | 바꿀 수 없음. 실습용이면 그대로 진행하거나 프로젝트를 새로 만들기 |
| 30일 뒤 평가 화면이 멈춤 | 테스트 모드로 만든 경우. 3단계 규칙으로 교체 |
| 잘못 낸 평가를 지우고 싶음 | 화면에서는 못 지움(규칙). 담당자가 Firebase 콘솔 데이터 탭에서 삭제 |

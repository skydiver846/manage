> ⏱ **2일차 7~9교시, 세 교시(150분)를 이 모듈 하나로 진행합니다.** 각자 준비해 온 **개인 관심사 한 가지**로 PRD를 쓰고, 그 PRD를 Claude Code에 건네 화면을 만들고, 검토해서 웹에 공개한 뒤, 휴대폰으로 써 보고 한 번 더 고칩니다. 09(화면 구조)와 10(손으로 배포)은 과정 뒤 복습 자료로 돌립니다.

> 🧑‍🏫 **바꾼 이유 (1차 교육 2일차):** 1일차가 약 4시간 만에 끝났고 로그인 문제도 거의 없었습니다. 교육생이 빨리 따라오므로 09·10의 작은 실습은 넘기고, 과정의 마지막 장면인 **"내가 생각한 것을 내가 만들어 쓴다"** 를 한 사람의 주제로 처음부터 끝까지 제대로 해 봅니다. Claude Code 화면과 메뉴 이름은 자주 바뀌니 강사 화면으로 한 단계씩 먼저 보여 주세요.

여행 준비물 화면으로 배운 흐름을, 이번에는 **내가 좋아하는 일**로 처음부터 끝까지 해 봅니다.

```그림
 7교시   ① 저장소·Claude Code 연결 → ② 관심사 PRD 인터뷰 → ③ PRD 건네고 계획 요청
 8교시   ④ 계획 확인·승인 → ⑤ 만들기 v0.1 → ⑥ 검토 → ⑦ 합치고 배포
 9교시   ⑧ 휴대폰으로 시험 → ⑨ 고치기 v0.2 (미리보기로 확인 후 합치기) → ⑩ 사용 설명·PRD 정리
```

이 모듈의 핵심은 "AI가 해 준다"가 아니라 아래 순서를 지키는 것입니다.

| 순서 | 누가 | 무엇을 |
|---|---|---|
| 기획 | **사람** | 무엇을, 누구를 위해, 어디까지 만들지 PRD로 정한다 |
| 계획 | AI → **사람 승인** | AI가 만들 방법을 먼저 말하고, 사람이 승인한 뒤에 만든다 |
| 만들기 | AI | 코드를 쓰고, 스스로 시험하고, 연습장(브랜치)에 저장한다 |
| 검토·결재 | **사람** | 표·질문·화면으로 확인하고, 합치기(결재)를 누른다 |
| 확인 | **사람** | 휴대폰에서 PRD의 성공 기준을 직접 해 본다 |

```그림
 내 PRD ──▶ Claude Code ──▶ 계획 ──(승인)──▶ 브랜치에 만들기 ──(검토)──▶ 합치기 ──▶ main ──▶ Netlify ──▶ 📱 내 화면
   ▲                                                                                                  │
   └──────────────────────────────── 써 보고 고칠 점 (v0.2) ◀─────────────────────────────────────────────┘
```

> 💡 모듈 08의 AI 브라우저(Aside)는 **웹사이트 화면**을 조작했습니다. Claude Code는 **저장소의 파일과 코드**를 조작합니다. 둘 다 "AI가 손을 움직이고, 사람이 승인한다"는 점은 같습니다.

## 주제 고르기: 내 관심사 한 가지

어제 안내한 대로 **개인 관심사 하나**를 준비해 왔습니다. 업무가 아니어도 됩니다. 이 모듈에서는 아래 조건에 맞게 크기를 줄입니다.

| 조건 | 이유 |
|---|---|
| **화면 1장, 핵심 기능 3개** | 한 시간 안에 만들고 검토할 수 있는 크기 |
| 기록은 **이 휴대폰(브라우저)에만** 저장 | 로그인·여러 사람 공유(데이터베이스)는 이번 범위 밖 |
| 실제 이름·연락처·주소를 넣지 않음 | 배포한 주소는 **누구나 열 수 있습니다** |

| 관심사 | 이런 화면으로 |
|---|---|
| 운동·등산 | 운동 기록과 이번 주 횟수·시간 합계, 목표 달성률 |
| 독서 | 읽은 책 목록, 별점, 이번 달 읽은 쪽수 |
| 반려동물 | 산책·사료·병원 기록, 다음 접종일 D-day |
| 캠핑·낚시 | 준비물 체크리스트와 챙김률, 장소별 메모 |
| 텃밭·화분 | 작물별 물 준 날, 다음에 줄 날 알림 표시 |
| 가계부·저축 | 항목별 지출 합계, 이번 달 남은 예산 |
| 아이 공부 | 과목별 공부 시간, 칭찬 스티커 개수 |

> 🧑‍🏫 주제를 못 정한 교육생은 위 표에서 고르게 하거나, 어제 05에서 쓴 **내 PRD**를 그대로 써도 됩니다(그 경우 ②를 건너뛰고 1일차 PRD의 `## 바꿀 점` 3가지만 반영). 그래도 막히면 아래 **부록: 공공데이터로 하기**로 안내합니다.

## ① 저장소 만들고 Claude Code 연결하기 (7교시, 15분)

GitHub은 **파일과 고친 기록을 보관하는 창고**입니다(가입은 사전 과제). 고칠 때마다 남기는 기록(**커밋**)은 게임의 **세이브 포인트**라서, 화면이 망가져도 그 시점으로 돌아갈 수 있습니다. 오늘은 Claude Code가 이 창고에 코드를 쓰고, Netlify가 창고를 지켜보다가 바뀌면 **저절로 다시 배포**합니다.

**저장소 만들기**
1. `github.com` 로그인 → 오른쪽 위 **[+]** → **[New repository]**
2. **Repository name**: `my-tool`
3. **Private** 선택
4. **Add a README file** ✅ 체크 (빈 저장소면 Claude Code가 작업을 시작하지 못합니다)
5. **[Create repository]**

**Claude Code 연결**
1. 업무 Chrome 프로필에서 `claude.ai/code` 접속 (웹 버전이라 설치가 필요 없습니다)
2. **GitHub 연결** (PC에 프로그램을 까는 것이 아니라, 브라우저에서 **Claude에게 내 GitHub 출입 권한을 주는** 과정입니다)
   - 화면의 **[GitHub 연결]**(Connect GitHub) 버튼 → GitHub 로그인(사전 과제에서 만든 계정)
   - **Install Claude** 권한 화면이 나오면 **Only select repositories** → `my-tool` **하나만** 고르고 → **[Install]** (영어 버튼 이름이 Install이라 "설치"라고 부릅니다)
   - 다시 `claude.ai/code` 화면으로 돌아옵니다
3. 작업할 저장소로 `my-tool` 을 고릅니다. 목록에 보이면 준비 완료입니다.

> 💡 **왜 저장소 하나만 열어 줄까?** 로그인은 "누구인지 확인"하는 **사원증**, 저장소 선택은 "어느 방에 들어갈 수 있는지" 정하는 **출입 권한**입니다. AI에게도 **필요한 방 하나만** 열어 줍니다.

> 🧑‍🏫 처음 연결할 때 권한 승인 화면이 여러 번 나옵니다. 강사 화면으로 한 단계씩 같이 하고, 먼저 끝난 사람이 옆 사람을 돕게 합니다. GitHub 새 기기 인증 메일이 오면 휴대폰 메일 앱에서 확인합니다. 15분 안에 안 되는 사람은 ②(PRD 인터뷰)를 먼저 하게 하고 강사가 따로 붙습니다.

## ③ PRD 건네고 계획 먼저 받기 (7교시 끝, 5분)

GitHub 연결은 Claude Code에게 저장소 **출입 권한**을 준 것일 뿐, 내 PC(옵시디언)에 있는 PRD는 아직 Claude가 볼 수 없습니다. 그래서 PRD를 **Claude Code 입력창에 붙여넣고**, Claude가 직접 저장소에 `PRD.md` 파일로 저장하게 합니다. GitHub 화면에서 파일을 올릴 필요가 없습니다.

PRD가 저장소에 파일로 남으면 Claude Code가 언제든 다시 읽을 수 있고, 고친 기록(⑨의 변경 기록)도 쌓입니다. 설계도를 공사 현장 사무실 벽에 붙여 두는 것과 같습니다.

그리고 바로 만들라고 하지 않고 **계획부터** 받습니다. 공사 전에 시공 계획서를 받아 보는 것과 같습니다. 계획 단계에서 잘못을 찾으면 1분이면 고치지만, 다 만든 뒤에 찾으면 10분이 걸립니다.

1. `claude.ai/code` 에서 저장소 `my-tool` 을 고릅니다.
2. 옵시디언에서 `PRD.md` 를 열어 전체 복사합니다 (Ctrl + A → Ctrl + C).
3. 아래 [바로 해 보기]의 칸에 붙여넣고 **[프롬프트 복사]** → Claude Code 입력창에 붙여넣어 보냅니다.

### 읽을거리: 깃허브에는 무엇을 올릴까? (쉬는 시간에)

방금 `PRD.md` 가 저장소에 올라갔습니다. 그렇다고 내 일과 관련된 파일을 **전부** 올리지는 않습니다. 깃허브에는 **다시 만들 수 없는 것**과 **사람이 직접 쓴 것**을 올리고, 프로그램이 자동으로 만들어 내는 것이나 남이 보면 안 되는 것은 뺍니다.

**보통 올리는 것**

- **코드 파일:** 이제 만들 `index.html` 같은 것
- **문서:** `PRD.md`, `README.md`, 사용 설명서
- **설정 파일:** 어떤 라이브러리를 쓰는지 적은 목록 같은 것
- **직접 만든 이미지·아이콘:** 화면에 들어가는 그림
- **테스트 코드:** 프로그램이 제대로 도는지 확인하는 코드

**보통 올리지 않는 것**

| 종류 | 예 | 이유 |
|---|---|---|
| 자동으로 생기는 결과물 | 빌드 결과 폴더, 임시 파일 | 코드만 있으면 언제든 다시 만들 수 있음 |
| 내려받은 외부 라이브러리 | `node_modules` 폴더 | 아주 크고, 목록만 있으면 다시 내려받을 수 있음 |
| **비밀 정보** | 비밀번호, API 키, `.env` 파일 | **한 번 올라가면 지워도 기록(커밋)에 남아** 위험함 |
| **개인정보·실제 사용 기록** | 고객·민원인 정보, 사용자가 입력한 데이터 | 코드와 데이터는 따로 보관함 |
| 내 컴퓨터 전용 설정 | 편집기 설정, `.DS_Store` | 다른 사람에게는 필요 없음 |
| 아주 큰 파일 | 동영상, 큰 데이터 파일 | 저장소가 무거워짐 (따로 보관하는 방법이 있음) |

빼야 할 파일은 보통 `.gitignore` 라는 파일에 이름을 적어 둡니다. 그러면 실수로 커밋하는 일을 막을 수 있습니다. 회사 문서로 치면 **"외부 반출 금지 목록"** 입니다.

**이번 실습에 대입하면**

| 구분 | 파일 |
|---|---|
| 올리는 것 | `PRD.md`(방금 올림), 만들 `index.html`, ⑩의 `README.md` |
| 올라가지 않는 것 | 화면에서 **내가 입력한 기록**. 사용자 데이터라서 내 휴대폰 브라우저(localStorage)에 남는 것이 맞습니다 |
| 판단이 필요한 것 | 참고 자료(후기 원문, 사진, 메모). 올려도 되고 안 올려도 됩니다. 실제 개발이라면 `docs/` 폴더에 함께 두는 경우가 많습니다. 단, 실명·연락처가 있으면 올리지 않습니다 |

> 🧑‍🏫 업무로 옮길 때 가장 중요한 줄은 **비밀 정보**와 **개인정보**입니다. "저장소가 비공개라서 괜찮다"가 아니라, **애초에 올리지 않는 것**이 원칙입니다. 커밋 기록은 지워도 남기 때문입니다.

## ④ 계획 확인하고 승인하기 (8교시 시작, 10분)

1. Claude가 내놓은 **화면 그림**과 **기능 3줄**을 PRD와 비교합니다. PRD에 없는 기능이 끼어 있으면 "○○는 빼 줘"라고 합니다.

## ⑤ 만들기 v0.1 (8교시, 15분)

## ⑥ AI가 한 일 검토하기 (8교시, 10분) ⭐

**결재하기 전에 기안문을 훑어보는 것**과 같습니다. 코드는 읽지 않습니다. 아래 **네 가지만** 확인합니다.

| | 확인할 것 | 왜 |
|---|---|---|
| 1 | **시키지 않은 기능**을 넣었나? | 좋아 보여도 PRD에 없는 기능은 고장과 혼란의 원인 |
| 2 | **다른 사이트로 연결**되는 것이 있나? | 내 화면을 연 사람의 정보가 밖으로 나갈 수 있음 |
| 3 | **실제 이름·전화번호** 같은 것이 들어갔나? | 배포 주소는 누구나 열 수 있음 |
| 4 | "확인했다"는 것이 **진짜 시험한 것**인가? | AI가 스스로 매긴 점수일 뿐. 진짜 확인은 ⑧에서 내 휴대폰으로 |

| 확인할 것 | 예/아니요 | 있다면 무엇인지 |
|---|---|---|
| PRD에 없는 기능을 넣은 것이 있나? | | |
| 다른 사이트(외부 주소)에서 불러오거나 보내는 것이 있나? | | |

그리고 화면에 무엇이 있고 어떻게 쓰는지 3줄로, 내가 휴대폰에서 꼭 눌러 봐야 할 곳 3군데를 알려 줘.

**그다음, 답 보고 고치기 (5분)**

## ⑦ 합치고 배포하기 (8교시, 15분)

두 가지를 합니다. **(가) 합치기**로 연습장(브랜치)의 화면을 원본(`main`)에 넣고, **(나) Netlify 연결**로 원본을 웹 주소로 공개합니다. Netlify 연결은 **처음 한 번만** 하면, 그다음부터는 합칠 때마다 저절로 다시 배포됩니다.

```그림
 Claude Code ──[Create PR] 결재 올리기──▶ GitHub: 결재 요청서(PR) ──[Merge] 결재──▶ main ──(저절로)──▶ Netlify ──▶ 🌐 내 주소
                               (가) 합치기 = 결재                              (나) 처음 한 번 연결
```

### (가) 합치기 = 결재 (5분)

**PR**(풀 리퀘스트)은 "연습장의 내용을 원본에 합쳐도 될까요?"라는 **결재 요청서**입니다. 영어 버튼 두 개만 기억하면 됩니다.

| 버튼 | 어디에 | 뜻 |
|---|---|---|
| **[Create PR]** | Claude Code **채팅 옆 패널의 Changes(변경 사항) 카드** | 결재 요청서를 **올리기** (상신) |
| **[Merge pull request]** | GitHub 화면 | 결재하기 (원본에 합치기) |

1. **결재 올리기:** Claude Code 화면에서 **채팅 옆 패널**에 있는 **Changes**(변경 사항) 카드를 찾습니다. `+120 -0` 처럼 바뀐 줄 수가 적힌 카드입니다. 그 카드의 **[Create PR]** 을 누르면 결재 요청서(PR)가 제목·설명까지 채워져 바로 만들어집니다.
   - **채팅 옆 패널이 안 보이면:** 화면 맨 위 세션 제목 줄의 **패널 보기 아이콘**(Show session rail) 또는 **⋮** 메뉴에서 켭니다.
   - **그래도 못 찾겠으면:** 채팅창에 `결재 요청서(PR)를 만들어 주고 주소를 알려 줘` 라고 보내도 됩니다.
2. Changes 카드에 생긴 결재 요청서(PR) 제목이나, Claude가 알려 준 주소를 누르면 GitHub 화면이 열립니다.
3. 아래로 내려 초록 버튼 **[Merge pull request]** → **[Confirm merge]**
4. 보라색 **Merged** 표시가 보이면 끝입니다. 옆의 **[Delete branch]** 는 눌러도 되고 안 눌러도 됩니다(다 쓴 연습장 지우기).

### (나) Netlify에 연결하기 (처음 한 번, 10분)

1. `app.netlify.com` → **[Sign up]** → **GitHub** 로 가입합니다. (이미 GitHub에 로그인돼 있어 가장 빠릅니다)
   - 가입 질문(무엇에 쓸지, 팀 이름 등)이 나오면 아무거나 고르거나 **Skip** 합니다. 요금제를 물으면 **Free**(무료). 카드는 넣지 않습니다.
2. **[Add new project]**(또는 Add new site) → **[Import an existing project]** → **GitHub**
3. GitHub에서 **Netlify에게 출입 권한을 주는** 화면(Install Netlify)이 나옵니다 → **Only select repositories** → `my-tool` **하나만** 선택 → **[Install]**. 이것도 PC에 까는 것이 아닙니다.
4. 목록에서 `my-tool` 을 고르고, 설정은 **아무것도 바꾸지 않은 채** 맨 아래 **[Deploy my-tool]**(또는 Deploy) 를 누릅니다.
5. 1분쯤 지나 초록색 **Published** 가 보이면, 위쪽의 `○○○.netlify.app` 주소를 눌러 PC에서 내 화면이 열리는지 봅니다.
6. 주소 이름 바꾸기: **Project configuration**(또는 Site configuration) → **Change project name** → 예) `run-log-hong` → `https://run-log-hong.netlify.app` (이미 있는 이름이면 뒤에 숫자를 붙입니다)

> ⚠️ **배포한 주소는 누구나 열 수 있습니다.** 저장소가 비공개여도 마찬가지입니다. 화면에 실제 이름·연락처·내부 자료가 없는지 한 번 더 봅니다.

> ⚠️ **Netlify 연결이 막히면:** GitHub `my-tool` 저장소에서 `index.html` 을 눌러 **[Download raw file]**(⬇ 아이콘)로 내려받아 `my-tool` 폴더에 넣고, Netlify에 **로그인한 상태에서** `app.netlify.com/drop` 에 폴더째 끌어다 놓습니다. 로그인하지 않고 올리면 1시간 뒤 사라집니다. 이 방법은 ⑨부터 고칠 때마다 다시 끌어다 놓아야 합니다.

> 🧑‍🏫 영어 버튼이 이어지는 구간이라 강사 화면으로 한 단계씩 같이 합니다. 가장 많이 막히는 곳은 (나)의 3번(권한 화면)과 4번(목록에 `my-tool` 이 없음 → "자주 막히는 곳" 표)입니다. 먼저 끝난 사람이 옆 사람을 돕게 하세요.

## ⑩ 사용 설명과 PRD 정리 (9교시, 10분)

만든 것을 다른 사람에게 건넬 수 있게 정리합니다. 나중의 나도 "다른 사람"입니다.

```
이 저장소의 README.md를 이 화면의 사용 설명서로 바꿔 줘.
- 이 화면이 무엇이고 누구를 위한 것인지 2줄
- 배포 주소
- 쓰는 방법 3단계
- 기록이 어디에 저장되는지와 주의할 점(브라우저 기록을 지우면 사라짐)
- PRD.md와 변경 기록 위치
커밋 메시지는 "사용 설명 추가". 결재 요청서(PR)까지 올려 줘.
```

- GitHub에서 그 결재 요청서를 **[Merge pull request]** 로 합칩니다(README만 바뀌므로 화면은 그대로).
- 저장소에 **PRD.md(설계도) · index.html(화면) · README.md(설명서)** 세 가지가 남았는지 확인합니다. 이 셋이 있으면 언제든 같은 방법으로 v0.3을 만들 수 있습니다.

> 🧑‍🏫 시간이 남는 교육생에게는 **"더 해 보기"** 를 권합니다. 예) "기록을 CSV로 내려받는 버튼 추가", "다크 모드", "이번 달 그래프". 단, 한 번에 하나씩, PRD의 `다음에` 목록에 먼저 적고 나서 지시하게 합니다.

## 부록: 공공데이터로 하기 (관심사가 없을 때)

관심사를 정하지 못했거나 PRD가 잘 안 나오면 공공데이터 파일로 현황 화면을 만듭니다. ②·③을 아래로 바꾸고, ④부터는 같습니다. CSV 파일은 붙여넣기에 크므로 GitHub 화면에서 직접 올립니다.

| 구분 | 파일 (공공데이터포털에서 이 이름으로 검색) | 만들어 볼 화면 |
|---|---|---|
| **기본** | 소방청_화재인명피해 지역별 성별 현황 | 시도별 사상자 막대그래프, 전국 평균보다 많은 지역 강조 |
| 대안 | 소방청_가스누출(폭발) 화재 발생 현황 | 연도·장소별 건수, 많은 장소 순위 |

1. `data.go.kr` 에서 파일 이름으로 검색 → **파일데이터** → **[다운로드]**
2. 받은 파일 이름을 `data.csv` 로 바꾸기 (탐색기 **보기 → 파일 확장명** 을 켜 두어야 `data.csv.csv` 가 되지 않습니다)
3. GitHub `my-tool` → **[Add file] → [Upload files]** → `data.csv` → **[Commit changes]**
4. Claude Code에 아래 [바로 해 보기]의 지시문을 붙여넣습니다.

## 마무리: 꾸준히 하면 업무 자동화까지

이틀 동안 사다리를 다섯 칸 올라왔습니다. 마지막 칸은 **정해진 때 저절로 돌아가게** 하는 것입니다.

```그림
① 잘 시키기      6하원칙 프롬프트                       (03)
② 자료 맡기기    프로젝트 · MD 파일                     (03 · 05)
③ 방법 맡기기    스킬 = 업무 매뉴얼                     (06)
④ 클릭 맡기기    AI 브라우저 · 루틴                     (08)
⑤ 내 도구 만들기 PRD → Claude Code → 검토 → 배포       (07 · 12)  ← 오늘 여기까지
⑥ 저절로 돌아가게 정해진 때 자동 실행, 여러 사람 자료 모으기  (다음 단계)
```

- 오늘은 관심사로 했지만 **순서는 업무에서도 똑같습니다.** PRD를 쓰고, 계획을 먼저 받고, 검토하고, 결재(합치기)하고, 써 보고 고칩니다.
- 한 번에 다 하지 않아도 됩니다. **일주일에 한 번, 30분**이면 됩니다.

| 주 | 사다리 | 해 볼 것 | 다 했으면 |
|---|---|---|---|
| 1주 | ①② 잘 시키기 · 자료 맡기기 | 내 업무 **프로젝트**를 만들어 규정·양식을 넣고, 업무 질문을 그 안에서 하기 | □ |
| 2주 | ③ 방법 맡기기 | **내 업무 스킬**을 실제 문서에 3번 쓰고, 고칠 점을 반영해 다시 올리기 | □ |
| 3주 | ④ 클릭 맡기기 | 매주 반복하는 웹 확인 작업 하나를 **AI 브라우저 루틴**으로 만들기 | □ |
| 4주 | ⑤ 내 도구 만들기 | 오늘 만든 관심사 화면을 **v0.3**으로 고치거나, 같은 순서로 **업무 화면** 하나를 PRD부터 만들어 동료 1명에게 써 보게 하기 | □ |

- 여는 이야기의 **여행길 도우미**는 한 칸 더 간 모습입니다. 날씨·주차처럼 **실시간 정보**가 필요하면 서버와 공공데이터 API를 씁니다. 오늘 만든 화면(기록은 내 브라우저에만)의 다음 단계입니다.

### 처음 질문, 다시 (10교시 시작, 2분)

첫날 1교시에 물었던 세 문장입니다. 지금은 어떤가요?

① **AI는 검색을 조금 편하게 해 주는 것**이다  
② **프로그램은 개발자만** 만든다  
③ 나는 **컴퓨터를 잘 못해서** 어렵다

결과 공유는 한 사람씩 **"나는 ○○를 만들어 ○○에 쓴다"** 한 줄로 시작하고, 휴대폰으로 내 화면을 보여 줍니다. 그리고 **"업무에서는 ○○에 쓰겠다"** 를 한 줄 덧붙입니다. 예) "나는 등산 기록 화면을 만들어 이번 달 산행 횟수를 본다. 업무에서는 교육 장비 대여 대장을 같은 방법으로 만들겠다."

# 모듈 12 (심화 4). Claude Code로 한 번에 만들고 배포하기

← [[11_(심화) Firebase로 공용 장부 연결]]

📌 **이 과정의 Claude Team 계정에는 Claude Code가 포함되어 있어 모두 직접 실습합니다.**

> ⚠️ **리허설 전 모듈입니다.** Claude Code 화면과 메뉴 이름은 자주 바뀝니다. 강의 전에 Team 계정(교육생과 같은 좌석)으로 처음부터 끝까지 한 번 해 보고 문구를 맞춰 주세요.

모듈 10에서는 파일을 **손으로** 올리고(커밋), 연필로 고쳤습니다. 이번에는 같은 일을 **AI 에이전트(Claude Code)** 에게 맡깁니다. 말로 지시하면 Claude가 저장소의 파일을 직접 읽고, 고치고, 시험하고, 커밋·푸시까지 합니다.

모듈 08의 AI 브라우저(Aside)가 **웹사이트 화면**을 조작했다면, Claude Code는 **저장소의 파일과 코드**를 조작합니다.

이 모듈의 핵심은 "AI가 해 준다"가 아니라 **"AI가 한 일을 내가 검토하고 승인한다"** 입니다.

```
 모듈 10 (손으로):  나 ── 복사·붙여넣기 ──▶ GitHub ──▶ Vercel
 모듈 12 (AI와):    나 ── 지시 ──▶ Claude Code ── 커밋·푸시 ──▶ GitHub ──▶ Vercel
                     ▲                                          │
                     └──────────── 변경 내용 검토·승인 ◀──────────┘
```

> 💡 모듈 6에서 만든 **스킬**은 Claude Code에서도 같은 방식으로 씁니다. 업무 방법을 SKILL.md로 적어 두면, 사람에게 하듯 AI 에이전트에게도 매뉴얼을 건넬 수 있습니다.

## 이 과정의 진행 (Claude Team)

| 누가 | 하는 일 |
|---|---|
| **교육생 모두** | 각자 자기 `menu-survey` 저장소에서 1~6단계 |
| 강사 | 앞 화면에서 한 단계 먼저 보여 주고, 4단계(검토)는 함께 읽기 |

> 🧑‍🏫 Team 관리자 설정에서 **Claude Code** 가 허용돼 있어야 합니다. Claude Code는 Team 모든 좌석에 포함됩니다(2026-10 요금 페이지 기준). 강의 전날 교육생 좌석 계정으로 `claude.ai/code` 가 열리는지 확인하세요.
> 무료 계정으로 진행하게 되면 이 모듈은 강사 시연 + 교육생 검토로 바꿉니다(보존해 둔 무료 계정판 참고).

## 0단계: 준비 (10분)

1. 업무 Chrome 프로필에서 `claude.ai/code` 접속 (Claude Code **웹 버전**. 프로그램 설치가 필요 없어 행정망 PC에 적합)
2. **GitHub 연결**: 안내에 따라 Claude GitHub 앱을 설치
   - 저장소 선택에서 **Only select repositories** → `menu-survey` **하나만** 선택
3. 작업할 저장소로 `menu-survey` 선택

> 🧑‍🏫 2번에서 "모든 저장소(All repositories)"를 고르지 않게 합니다. **AI에게는 필요한 저장소만 열어 준다**, 이것이 오늘의 첫 번째 보안 습관입니다.
> 행정망에서 `claude.ai/code` 가 열리는지, GitHub 앱 설치 화면이 막히지 않는지 강의장 접속 점검 때 함께 확인하세요.

## 1단계: PRD에 새 기능 추가 (10분)

새 기능을 하나 정해 옵시디언 PRD에 먼저 적습니다(**v0.5**). 기준 문서는 언제나 PRD입니다.

**예시 기능: 결과 내려받기** (결과보고서에 붙일 표를 엑셀에서 다시 정리하지 않기)
- 4번 핵심 기능에 추가: "있으면 좋음 | 결과 내려받기 | [결과 내려받기] 버튼을 누르면 메뉴·식사별 결과표를 엑셀에서 열 수 있는 CSV 파일로 저장"
- 6번 범위 밖에서 "엑셀 내보내기" 삭제 (이제 범위 안)
- 7번 성공 기준에 추가: "- [ ] 내려받은 파일을 엑셀로 열면 메뉴·식사·응답 수·평균·상태 칸이 보이고, 순서가 화면 결과표와 같다"

## 2단계: Claude Code에 지시하기 (5분)

```
이 저장소의 index.html은 구내식당 메뉴 만족도 집계 화면이야.
아래 PRD v0.5의 "결과 내려받기" 기능을 추가해 줘.

(여기에 PRD v0.5의 4번·7번 칸 붙여넣기)

- index.html 파일 하나만 고치고, 나머지 기능과 디자인은 그대로 둬
- 한글이 엑셀에서 깨지지 않게 해 줘
- 고친 뒤 브라우저에서 동작을 시험해 보고 결과를 알려 줘
- 커밋 메시지는 한국어로 "결과 내려받기 기능 추가"
```

> 🧑‍🏫 모듈 3의 공식(역할·목표·맥락·형식·조건)이 그대로 쓰였습니다. 특히 **"파일 하나만, 나머지는 그대로"** 같은 범위 조건이 AI 에이전트에게는 더 중요합니다. 범위를 안 정하면 필요 없는 곳까지 고칩니다.

## 3단계: Claude가 일하는 모습 지켜보기 (10분)

화면에 Claude가 하는 일이 차례로 나타납니다.

| 보이는 것 | 뜻 |
|---|---|
| 파일 읽기 | 지금 코드가 어떻게 되어 있는지 파악 |
| 파일 고치기 (초록·빨강 줄) | 추가한 줄(초록)과 지운 줄(빨강) |
| 시험 실행 | 고친 기능이 동작하는지 확인 |
| 커밋·푸시 | 변경 내용을 기록해 GitHub로 올림 |

- 중간에 **허락을 묻는 화면**이 나오면 무엇을 하려는지 읽고 승인합니다. 모르는 내용이면 승인하지 말고 강사에게 묻습니다.
- Claude Code는 보통 `main`(운영)이 아니라 **별도 작업 줄기(브랜치)** 에 올립니다. 원본을 바로 건드리지 않는 안전장치입니다.

## 4단계: AI가 한 일 검토하기 (10분) ⭐

GitHub 저장소에서 확인합니다.

1. 저장소 화면 위쪽 **브랜치 선택**(main 이라고 적힌 버튼) → Claude가 만든 브랜치 선택
2. **커밋 기록(시계 아이콘)** → Claude의 커밋 클릭
3. **초록 줄(추가)** 과 **빨강 줄(삭제)** 을 읽으며 확인:
   - PRD에 적은 기능만 바뀌었나?
   - 메뉴·식사별 집계·개선 필요 판정 같은 **원래 기능을 지우지 않았나?**
   - 모르는 외부 주소나 이상한 코드가 들어가지 않았나?

> 🧑‍🏫 옆 사람과 서로의 커밋 화면을 바꿔 보며 **함께** 검토하게 하면 좋습니다. "AI가 쓴 코드도 내 이름으로 나가면 내 책임"(모듈 2)을 다시 짚어 주세요. 모듈 09에서 HTML·CSS·JS를 읽어 본 경험이 여기서 쓰입니다.

## 5단계: 미리보기 배포로 확인 (5분)

Vercel은 브랜치마다 **미리보기(Preview) 주소**를 따로 만들어 줍니다.

1. Vercel 프로젝트 → **Deployments** → Claude 브랜치의 배포 → **Visit**
2. 미리보기 주소에서 만족도 몇 건 제출 → [결과 내려받기] → 엑셀로 열어 PRD 성공 기준 확인
3. 운영 주소(Domains)는 **아직 그대로**인지 확인

| 주소 | 무엇을 보여 주나 |
|---|---|
| 미리보기 (Preview) | 아직 합치기 전, Claude 브랜치의 결과 |
| 운영 (Production, Domains) | `main` 의 결과. 이용자가 실제로 만족도를 내는 주소 |

## 6단계: 합치기 → 운영 반영 (5분)

1. GitHub에서 **Compare & pull request** (또는 Claude Code 화면의 PR 만들기)
2. 변경 내용을 마지막으로 확인 → **Merge pull request** → **Confirm merge**
3. Vercel이 `main` 을 다시 배포 → 운영 주소에서 새 기능 확인

```
 Claude 브랜치 ──(미리보기에서 확인)──▶ 합치기(Merge) ──▶ main ──▶ 운영 주소에 반영
```

> 🧑‍🏫 마무리 멘트: "손으로 하면 30분, AI에게 맡기면 5분. 대신 **검토(4단계)와 확인(5단계)은 사람이 합니다.** 이 순서를 지키면 AI를 믿고 쓸 수 있습니다."

> 💡 같은 방법을 **강의평가 결과 집계**(과목·교관별)에도 그대로 쓸 수 있습니다. 메뉴를 과목으로, 점심·저녁을 교관으로 바꾸면 PRD → 화면 → 장부 → 배포 흐름이 똑같습니다.

## 자주 막히는 곳

| 상황 | 해결 |
|---|---|
| `claude.ai/code` 에 들어가지지 않음 | Team 화면이 맞는지 확인(왼쪽 아래 Team 이름). 맞으면 관리자 설정에서 Claude Code 허용 여부 확인. 행정망 차단이면 전산 담당자 문의 |
| 저장소 목록에 `menu-survey` 이 없음 | GitHub 앱 설정에서 해당 저장소 접근 허용 추가 |
| Claude가 여러 파일을 고침 | 지시문에 "index.html 하나만" 조건이 있는지 확인. 원치 않으면 합치지 않고 지시를 다시 |
| 미리보기 주소가 안 보임 | Vercel **Deployments** 에서 Claude 브랜치 배포가 Ready 인지 확인 |
| 내려받은 CSV가 엑셀에서 깨짐 | "엑셀에서 한글이 깨지지 않게" 조건을 넣어 다시 요청 |
| 잘못 합쳤음 | Vercel **Instant Rollback** 으로 이전 배포로 즉시 되돌리고, GitHub에서 되돌리기(Revert) |

4. AI에게 맡긴 뒤에도 **사람이 꼭 하는 두 가지**는? (정답: 변경 내용 검토, 미리보기에서 확인)

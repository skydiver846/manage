> 🤔 **생각해 보기:** AI가 만든 화면을 그대로 공개해도 될까요? 공개 전에 무엇을 확인해야 할까요? (답은 이 모듈에서 찾아보세요. 점수 없음)

📌 **이 과정의 Claude Team 계정에는 Claude Code가 포함되어 있어 모두 직접 실습합니다.**

> 🧑‍🏫 **리허설 전 모듈입니다.** Claude Code 화면과 메뉴 이름은 자주 바뀝니다. 강의 전에 Team 계정(교육생과 같은 좌석)으로 처음부터 끝까지 한 번 해 보고 문구를 맞춰 주세요.

모듈 10에서는 준비물 화면을 **손으로** 끌어다 놓아 배포했습니다. 이번에는 어제 쓰고 다듬은 **내 PRD**를 **AI 에이전트(Claude Code)** 에게 건네, 어제 시안으로 본 **내 화면을 제대로 만들어 웹에 공개**합니다. 말로 지시하면 Claude가 저장소에 파일을 만들고, 시험하고, 커밋·푸시까지 합니다. 사람은 검토하고 승인한 뒤 배포합니다.

과정의 마지막 장면은 **각자 자기 PRD로 만든 화면을 휴대폰으로 여는 것**입니다. 여행 준비물 화면을 따라 만들었던 그 흐름을, 이번엔 내 주제로 합니다.

모듈 08의 AI 브라우저(Aside)가 **웹사이트 화면**을 조작했다면, Claude Code는 **저장소의 파일과 코드**를 조작합니다.

이 모듈의 핵심은 "AI가 해 준다"가 아니라 **"AI가 한 일을 내가 검토하고 승인한다"** 입니다.

```
 모듈 10 (손으로):  나 ── 폴더 끌어다 놓기 ─────────────────────────▶ Netlify
 모듈 12 (AI와):    나 ── 지시 ──▶ Claude Code ── 커밋·푸시 ──▶ GitHub ──▶ Netlify (저절로)
                     ▲                                          │
                     └──────────── 변경 내용 검토·승인 ◀──────────┘
```

> 💡 모듈 6에서 만든 **스킬**은 Claude Code에서도 같은 방식으로 씁니다. 업무 방법을 SKILL.md로 적어 두면, 사람에게 하듯 AI 에이전트에게도 매뉴얼을 건넬 수 있습니다.

## 0단계: 준비 확인 (2분)

모듈 10의 **7번**에서 `my-tool` 저장소를 만들고 Claude Code에 연결해 두었습니다.

1. 업무 Chrome 프로필에서 `claude.ai/code` 접속
2. 작업할 저장소로 `my-tool` 선택

**아직 안 했다면** 모듈 10의 7번(①저장소 만들기, ②Claude Code 연결)을 지금 합니다(약 10분). 저장소는 **Private**, README 체크, GitHub 앱은 **Only select repositories → `my-tool` 하나만**입니다.

> 🧑‍🏫 0단계에서 막힌 사람이 많으면 옆 사람과 짝을 지어 먼저 된 사람이 도와주게 합니다. **AI에게는 필요한 저장소만 열어 준다**는 보안 습관을 한 번 더 짚습니다.

## 1단계: 내 PRD 다듬기 (5분)

내 업무 폴더 `01_기획(PRD)` 의 **내 PRD**를 열어, 어제 07-3 화면 시안에서 메모한 **바꾸고 싶은 점 3가지**를 먼저 반영하고(아직 안 했다면) 아래 세 가지를 확인합니다.

| 확인 | 이유 |
|---|---|
| **4번 핵심 기능**이 3~5개인가? | 한 시간 안에 만들 수 있는 크기. 많으면 "있으면 좋음"은 다음으로 |
| **6번 범위 밖**에 "로그인, 여러 사람 공유(데이터베이스)" 가 있나? | 기록은 **이 브라우저에만** 저장하는 화면으로 만든다 (10에서 확인한 한계 그대로) |
| 실제 이름·연락처·내부 자료가 들어 있지 않나? | 저장소와 AI에게 건네는 내용이므로 예시로 바꾼다 |

## 1단계-B: 공공데이터 파일 준비 (B를 고른 경우, 5분)

아래 두 파일 중 하나를 고릅니다. 처음이면 **기본**을 권합니다.

| 구분 | 파일 (공공데이터포털에서 이 이름으로 검색) | 크기 | 만들어 볼 화면 |
|---|---|---|---|
| **기본** | 소방청_화재인명피해 지역별 성별 현황 | 작은 표 | 시도별 사상자 막대그래프, 전국 평균보다 많은 지역 강조 |
| 대안 | 소방청_가스누출(폭발) 화재 발생 현황 | 약 300줄 | 연도·장소별 건수, 많은 장소 순위 |

1. `data.go.kr` (공공데이터포털)에서 위 파일 이름으로 검색 → **파일데이터** → **[다운로드]** (로그인 없이 받을 수 있음)
2. 받은 파일 이름을 `data.csv` 로 바꾸기 (한글·띄어쓰기가 든 파일 이름은 웹 주소에서 말썽이 날 수 있음)
3. GitHub `my-tool` 저장소 → **[Add file] → [Upload files]** → `data.csv` 끌어다 놓기 → **[Commit changes]**

> (과정 뒤) 더 큰 자료로 해 보고 싶으면 **소방청_연간화재통계**(약 3만 7천 줄, 화재 1건 = 1줄)로 시도·장소·발화요인별 집계를 만들어 봅니다. 파일이 커서 시간이 더 걸립니다.

> 공공데이터는 **누구나 쓸 수 있게 공개된 자료**라 비공개 저장소에 올려도, 배포해서 보여 줘도 됩니다. 다만 화면에 **출처(공공데이터포털, 제공기관, 기준일)** 를 꼭 적습니다.

## 2단계: Claude Code에 지시하기 (5분)

**A. 내 PRD 화면**

```
이 저장소에 아래 PRD의 화면을 만들어 줘.

(여기에 내 PRD 전체를 붙여넣기)

- index.html 파일 하나로 만들고, 외부 서버나 데이터베이스 없이 기록은 이 브라우저(localStorage)에만 저장해 줘
- 휴대폰 화면(폭 약 400px)에서 가로 스크롤 없이 보이게 해 줘
- 실제 개인정보 대신 예시 데이터로 처음 화면을 보여 줘
- 다 만든 뒤 PRD 7번 성공 기준대로 시험해 보고, 기준마다 통과 여부를 표로 알려 줘
- 커밋 메시지는 한국어로 "내 PRD 화면 v0.1"
```

**B. 공공데이터 화면**
```
이 저장소의 data.csv는 공공데이터포털에서 받은 "[파일 이름]" 자료야.
이 데이터로 한눈에 보는 현황 화면을 index.html 파일 하나로 만들어 줘.

- 먼저 CSV의 칸 이름과 줄 수를 확인해 알려 주고, 어울리는 표·그래프 3가지를 제안한 뒤 첫 번째로 만들어 줘
- CSV가 EUC-KR(CP949)일 수 있으니 한글이 깨지지 않게 읽어 줘
- 외부 서버나 외부 프로그램(라이브러리) 없이 같은 저장소의 data.csv를 읽고, 그래프도 직접 그려 줘
- 휴대폰 화면(폭 약 400px)에서 가로 스크롤 없이 보이게 해 줘
- 화면 아래에 출처(공공데이터포털, 제공기관, 기준일)를 적어 줘
- 다 만든 뒤 화면의 숫자 3개를 CSV 원본과 대조해 맞는지 표로 알려 줘
- 커밋 메시지는 한국어로 "공공데이터 화면 v0.1"
```

> 🧑‍🏫 모듈 3의 공식(역할·목표·맥락·형식·조건)이 그대로 쓰였습니다. 맥락은 **PRD 한 장**이 대신합니다. 05에서 PRD를 공들여 쓴 이유가 여기서 드러납니다. "파일 하나만", "데이터베이스 없이" 같은 **범위 조건**이 AI 에이전트에게는 특히 중요합니다.

## 3단계: Claude가 일하는 모습 지켜보기 (15분)

화면에 Claude가 하는 일이 차례로 나타납니다.

| 보이는 것 | 뜻 |
|---|---|
| 파일 만들기 (초록 줄) | 새로 쓴 코드 |
| 시험 실행 | 만든 화면이 PRD 성공 기준대로 동작하는지 확인 |
| 커밋·푸시 | 만든 것을 저장해 GitHub 창고에 올림. 커밋은 **세이브 포인트**라 잘못돼도 이 시점으로 돌아갈 수 있음 |

- 중간에 **허락을 묻는 화면**이 나오면 무엇을 하려는지 읽고 승인합니다. 모르는 내용이면 승인하지 말고 손을 들어 주세요.
- Claude Code는 원본(`main`)을 바로 고치지 않고 **연습장(브랜치)** 에 먼저 올립니다. 게임으로 치면 본 저장 파일은 두고 **새 슬롯에 저장**하는 것입니다. 내가 확인하고 **합치기** 전까지는 실제 화면이 바뀌지 않는 안전장치입니다.

## 4단계: AI가 한 일 확인하기 (10분) ⭐

코드를 한 줄씩 읽지 않아도 됩니다. **표 · 질문 · 화면** 세 가지로 확인합니다.

먼저 **연습 보고서**로 3~4분 감을 잡은 뒤, 내 화면을 같은 눈으로 확인합니다.

<div class="lab" data-lab="review"></div>

1. **표 보기:** Claude가 마지막에 보여 준 표를 봅니다. **A**는 성공 기준 표를 내 PRD 7번과 비교, **B**는 숫자 대조 표에서 하나를 직접 CSV(엑셀)로 열어 맞는지 확인
2. **물어보기:** Claude Code에 이어서 입력합니다.

```
방금 만든 것을 코딩을 모르는 사람에게 설명하듯 알려 줘.
- 화면에 무엇이 있고 어떻게 쓰는지 3줄로
- PRD 범위 밖 기능을 넣은 것이 있는지
- 외부 주소나 실제 개인정보가 들어간 것이 있는지
```

3. 이상한 점이 있으면 "○○는 빼 줘", "○○가 PRD와 달라, 고쳐 줘"로 이어서 지시합니다.
4. **화면 보기**는 5단계에서 배포한 뒤 휴대폰으로 합니다.

> 🧑‍🏫 "AI가 쓴 코드도 내 이름으로 나가면 내 책임"을 다시 짚어 주세요. 코드를 읽을 수 있는 교육생에게는 GitHub 저장소 → **브랜치 선택** → Claude가 만든 브랜치 → **커밋 기록**에서 바뀐 코드를 직접 보게 합니다(모듈 09 경험). 입문자에게는 위 세 가지로 충분합니다.

## 5단계: 합치고 배포하기 (15분)

1. **합치기 (버튼 두 번):** Claude Code 화면의 **[PR 만들기]**(Create PR) → 열린 GitHub 화면에서 초록 버튼 **[Merge pull request]** → **[Confirm merge]**
   - PR(풀 리퀘스트)은 "연습장의 내용을 원본에 합쳐도 될까요?"라는 **결재 요청서**입니다. 합치기를 누르는 것이 **결재**입니다.
2. Netlify에서 **[Add new site] → [Import an existing project]** → **GitHub** 선택
   - 처음이면 Netlify GitHub 앱 설치 화면이 나옵니다 → **Only select repositories** → `my-tool` **하나만** 선택
3. 목록에서 `my-tool` → 설정은 **비워 둔 채로** (Build command 비움, Publish directory 비움) → **[Deploy]**
4. 주소 이름 바꾸기 (모듈 10의 3번): 예) `my-tool-hong` → `https://my-tool-hong.netlify.app`
5. 그 주소를 QR로 만들어 **내 휴대폰**으로 열기 (모듈 10의 4번)
6. **화면으로 확인:** PRD 7번 성공 기준 중 **3개**를 휴대폰에서 직접 해 봅니다. 안 되는 것이 있으면 Claude Code에 "○○가 안 돼, 고쳐 줘" → 다시 합치기 → 1~2분 뒤 같은 주소에 반영

```
 내 PRD ──▶ Claude Code ──▶ 브랜치 ──(검토)──▶ 합치기(Merge) ──▶ main ──▶ Netlify ──▶ 📱 내 화면
```

> ⚠️ **Netlify 연결이 막히면:** GitHub `my-tool` 저장소에서 `index.html`(B는 `data.csv` 도)을 내려받아 `my-tool` 폴더에 넣고, 모듈 10처럼 `my-tool` 폴더째 끌어다 놓습니다.

> 💡 모듈 10에서는 폴더를 손으로 끌어다 놓았습니다. 이제는 Netlify가 GitHub 창고를 지켜보다가 `main` 이 바뀌면 **저절로 다시 배포**합니다.

## 더 해 보기 (수업 뒤): 합치기 전에 미리보기로 확인

이제 저장소가 Netlify에 연결되어 있으니, 합치기 전에 **미리보기(Deploy Preview) 주소**로 먼저 확인할 수 있습니다.

1. Claude Code에 수정 하나를 지시: 예) "제목 아래에 사용 방법을 한 줄로 넣어 줘", "버튼 색을 소방 적색으로"
2. Claude Code 화면에서 **PR 만들기** → GitHub의 그 PR 화면에 Netlify가 남긴 **Deploy Preview** 링크(댓글 또는 아래쪽 확인 목록)를 눌러 미리보기 확인
3. 운영 주소(netlify.app)는 **아직 그대로**인지 확인 → 괜찮으면 합치기 → 1~2분 뒤 운영 주소에 반영

| 주소 | 무엇을 보여 주나 |
|---|---|
| 미리보기 (Deploy Preview) | 아직 합치기 전, Claude가 고친 결과 |
| 운영 (`○○.netlify.app`) | `main` 의 결과. 실제로 쓰는 주소 |

> 🧑‍🏫 마무리 멘트: "기획(PRD)은 사람이, 만드는 일은 AI가, **검토와 확인은 다시 사람이** 합니다. 이 순서를 지키면 AI를 믿고 쓸 수 있습니다." 같은 방법으로 준비물 화면에 "출발 D-day 표시" 같은 기능을 더하는 것도 됩니다.

## 마무리: 꾸준히 하면 업무 자동화까지

이틀 동안 사다리를 다섯 칸 올라왔습니다. 마지막 칸은 **정해진 때 저절로 돌아가게** 하는 것입니다.

```
① 잘 시키기      프롬프트 5요소                         (03)
② 자료 맡기기    프로젝트 · MD 파일                     (03 · 05)
③ 방법 맡기기    스킬 = 업무 매뉴얼                     (06)
④ 클릭 맡기기    AI 브라우저 · 루틴                     (08)
⑤ 내 도구 만들기 웹 화면 만들고 배포                   (07 · 09 · 10 · 12)  ← 오늘 여기까지
⑥ 저절로 돌아가게 정해진 때 자동 실행, 여러 사람 자료 모으기  (다음 단계)
```

- 한 번에 다 하지 않아도 됩니다. **일주일에 한 번, 내 업무 하나**에 한 칸씩 써 보는 것이 가장 빠릅니다. 구체적인 순서는 [[과제 안내]]의 "꾸준히 하기 4주 계획"에 있습니다.
- 처음에는 AI가 만든 것을 **내가 확인하고 승인**하는 습관이 가장 중요합니다. 오늘 12에서 한 것처럼요.
- 여는 이야기의 **여행길 도우미**는 한 칸 더 간 모습입니다. 날씨·주차처럼 **실시간 정보**가 필요하면 서버와 공공데이터 API(기상청, 한국교통안전공단)를 씁니다. 오늘 만든 화면(기록은 내 브라우저에만)의 다음 단계입니다.

## 자주 막히는 곳

| 상황 | 해결 |
|---|---|
| `claude.ai/code` 에 들어가지지 않음 | Team 화면이 맞는지 확인(왼쪽 아래 Team 이름). 맞으면 관리자 설정에서 Claude Code 허용 여부 확인. 행정망 차단이면 전산 담당자 문의 |
| 저장소 목록에 `my-tool` 이 없음 | GitHub 앱 설정에서 해당 저장소 접근 허용 추가 |
| Claude가 시작하지 못하고 저장소가 비었다고 함 | 저장소를 만들 때 **Add a README file** 을 체크하지 않은 것. GitHub에서 README를 하나 만들고 다시 |
| Claude가 여러 파일을 만듦 | 지시문에 "index.html 하나로" 조건이 있는지 확인. 원치 않으면 합치지 않고 지시를 다시 |
| 화면이 PRD와 다름 | PRD 7번 성공 기준을 구체적으로 고친 뒤 "이 기준대로 다시 맞춰 줘" |
| (B) 한글이 깨져 보임 | "data.csv가 EUC-KR이야. 한글이 깨지지 않게 다시 읽어 줘" |
| (B) 배포한 화면에 데이터가 안 나옴 | `data.csv` 가 저장소 맨 위(index.html과 같은 곳)에 있는지, 파일 이름 대소문자가 같은지 확인 |
| Netlify 목록에 `my-tool` 이 없음 | Netlify GitHub 앱 설정(**Configure the Netlify app on GitHub**)에서 `my-tool` 접근 추가 |
| 미리보기 주소가 안 보임 | PR 화면 아래 확인 목록이 끝날 때까지 1~2분 기다리기. Netlify 사이트 **Deploys** 에도 "Deploy Preview" 로 보임 |
| 잘못 합쳤음 | Netlify **Deploys** 에서 이전 배포 → **[Publish deploy]** 로 즉시 되돌리고, GitHub에서 되돌리기(Revert) |

# 모듈 12. 내 관심사로 PRD 쓰고, Claude Code로 만들어 배포하기

← [[08_AI 브라우저 Aside로 코딩 없이 업무 자동화]] | (과정 뒤 복습) [[09_(심화) HTML·CSS·JavaScript로 준비물 화면 뜯어보기]] · [[10_(심화) 프로토타입 배포]]

📌 **이 과정의 Claude Team 계정에는 Claude Code가 포함되어 있어 모두 직접 실습합니다.**

> ⏱ **2일차 7~9교시, 세 교시(150분)를 이 모듈 하나로 진행합니다.** 각자 준비해 온 **개인 관심사 한 가지**로 PRD를 쓰고, 그 PRD를 Claude Code에 건네 화면을 만들고, 검토해서 웹에 공개한 뒤, 휴대폰으로 써 보고 한 번 더 고칩니다. 09(화면 구조)와 10(손으로 배포)은 과정 뒤 복습 자료로 돌립니다.

> 🧑‍🏫 **바꾼 이유 (1차 교육 2일차):** 1일차가 약 4시간 만에 끝났고 로그인 문제도 거의 없었습니다. 교육생이 빨리 따라오므로 09·10의 작은 실습은 넘기고, 과정의 마지막 장면인 **"내가 생각한 것을 내가 만들어 쓴다"** 를 한 사람의 주제로 처음부터 끝까지 제대로 해 봅니다. Claude Code 화면과 메뉴 이름은 자주 바뀌니 강사 화면으로 한 단계씩 먼저 보여 주세요.

여행 준비물 화면으로 배운 흐름을, 이번에는 **내가 좋아하는 일**로 처음부터 끝까지 해 봅니다.

```그림
 7교시   ① 저장소·Claude Code 연결 → ② 관심사 PRD 인터뷰 → ③ PRD를 저장소에 올리기
 8교시   ④ 계획 먼저 받기(승인) → ⑤ 만들기 v0.1 → ⑥ 검토 → ⑦ 합치고 배포
 9교시   ⑧ 휴대폰으로 시험 → ⑨ 고치기 v0.2 (미리보기로 확인 후 합치기) → ⑩ 사용 설명·PRD 정리
```

이 모듈의 핵심은 "AI가 해 준다"가 아니라 아래 순서를 지키는 것입니다.

| 순서 | 누가 | 무엇을 |
|---|---|---|
| 기획 | **사람** | 무엇을, 누구를 위해, 어디까지 만들지 PRD로 정한다 |
| 계획 | AI → **사람 승인** | AI가 만들 방법을 먼저 말하고, 사람이 승인한 뒤에 만든다 |
| 만들기 | AI | 코드를 쓰고, 스스로 시험하고, 연습장(브랜치)에 저장한다 |
| 검토·결재 | **사람** | 표·질문·화면으로 확인하고, 합치기(결재)를 누른다 |
| 확인 | **사람** | 휴대폰에서 PRD의 성공 기준을 직접 해 본다 |

```그림
 내 PRD ──▶ Claude Code ──▶ 계획 ──(승인)──▶ 브랜치에 만들기 ──(검토)──▶ 합치기 ──▶ main ──▶ Netlify ──▶ 📱 내 화면
   ▲                                                                                                  │
   └──────────────────────────────── 써 보고 고칠 점 (v0.2) ◀─────────────────────────────────────────────┘
```

> 💡 모듈 08의 AI 브라우저(Aside)는 **웹사이트 화면**을 조작했습니다. Claude Code는 **저장소의 파일과 코드**를 조작합니다. 둘 다 "AI가 손을 움직이고, 사람이 승인한다"는 점은 같습니다.

## 주제 고르기: 내 관심사 한 가지

어제 안내한 대로 **개인 관심사 하나**를 준비해 왔습니다. 업무가 아니어도 됩니다. 이 모듈에서는 아래 조건에 맞게 크기를 줄입니다.

| 조건 | 이유 |
|---|---|
| **화면 1장, 핵심 기능 3개** | 한 시간 안에 만들고 검토할 수 있는 크기 |
| 기록은 **이 휴대폰(브라우저)에만** 저장 | 로그인·여러 사람 공유(데이터베이스)는 이번 범위 밖 |
| 실제 이름·연락처·주소를 넣지 않음 | 배포한 주소는 **누구나 열 수 있습니다** |

| 관심사 | 이런 화면으로 |
|---|---|
| 운동·등산 | 운동 기록과 이번 주 횟수·시간 합계, 목표 달성률 |
| 독서 | 읽은 책 목록, 별점, 이번 달 읽은 쪽수 |
| 반려동물 | 산책·사료·병원 기록, 다음 접종일 D-day |
| 캠핑·낚시 | 준비물 체크리스트와 챙김률, 장소별 메모 |
| 텃밭·화분 | 작물별 물 준 날, 다음에 줄 날 알림 표시 |
| 가계부·저축 | 항목별 지출 합계, 이번 달 남은 예산 |
| 아이 공부 | 과목별 공부 시간, 칭찬 스티커 개수 |

> 🧑‍🏫 주제를 못 정한 교육생은 위 표에서 고르게 하거나, 어제 05에서 쓴 **내 PRD**를 그대로 써도 됩니다(그 경우 ②를 건너뛰고 1일차 PRD의 `## 바꿀 점` 3가지만 반영). 그래도 막히면 아래 **부록: 공공데이터로 하기**로 안내합니다.

## ① 저장소 만들고 Claude Code 연결하기 (7교시, 15분)

GitHub은 **파일과 고친 기록을 보관하는 창고**입니다(가입은 사전 과제). 고칠 때마다 남기는 기록(**커밋**)은 게임의 **세이브 포인트**라서, 화면이 망가져도 그 시점으로 돌아갈 수 있습니다. 오늘은 Claude Code가 이 창고에 코드를 쓰고, Netlify가 창고를 지켜보다가 바뀌면 **저절로 다시 배포**합니다.

**저장소 만들기**
1. `github.com` 로그인 → 오른쪽 위 **[+]** → **[New repository]**
2. **Repository name**: `my-tool`
3. **Private** 선택
4. **Add a README file** ✅ 체크 (빈 저장소면 Claude Code가 작업을 시작하지 못합니다)
5. **[Create repository]**

**Claude Code 연결**
1. 업무 Chrome 프로필에서 `claude.ai/code` 접속 (웹 버전이라 설치가 필요 없습니다)
2. **GitHub 연결** (PC에 프로그램을 까는 것이 아니라, 브라우저에서 **Claude에게 내 GitHub 출입 권한을 주는** 과정입니다)
   - 화면의 **[GitHub 연결]**(Connect GitHub) 버튼 → GitHub 로그인(사전 과제에서 만든 계정)
   - **Install Claude** 권한 화면이 나오면 **Only select repositories** → `my-tool` **하나만** 고르고 → **[Install]** (영어 버튼 이름이 Install이라 "설치"라고 부릅니다)
   - 다시 `claude.ai/code` 화면으로 돌아옵니다
3. 작업할 저장소로 `my-tool` 을 고릅니다. 목록에 보이면 준비 완료입니다.

> 💡 **왜 저장소 하나만 열어 줄까?** 로그인은 "누구인지 확인"하는 **사원증**, 저장소 선택은 "어느 방에 들어갈 수 있는지" 정하는 **출입 권한**입니다. AI에게도 **필요한 방 하나만** 열어 줍니다.

> 🧑‍🏫 처음 연결할 때 권한 승인 화면이 여러 번 나옵니다. 강사 화면으로 한 단계씩 같이 하고, 먼저 끝난 사람이 옆 사람을 돕게 합니다. GitHub 새 기기 인증 메일이 오면 휴대폰 메일 앱에서 확인합니다. 15분 안에 안 되는 사람은 ②(PRD 인터뷰)를 먼저 하게 하고 강사가 따로 붙습니다.

## ② 관심사 PRD 인터뷰 (7교시, 25분)

어제 06에서 등록한 **PRD 인터뷰 스킬**이 여기서 다시 쓰입니다. **Claude 일반 대화**(claude.ai, Claude Code 아님)에서 새 대화를 열고 아래 [바로 해 보기]로 프롬프트를 만들어 붙여넣습니다.

<div class="lab" data-lab="fill" data-tpl="interest-prd" data-time="약 25분"></div>

```
너는 경험 많은 기획자야. 나는 개인 관심사로 "(만들고 싶은 것)" 화면을 휴대폰용으로 하나 만들려고 해.
지금은 (지금 하는 방법). 가장 불편한 점은 (불편한 점).
PRD를 쓰기 위해 나를 인터뷰해 줘.
- 한 번에 질문 1~2개만 해.
- 배경·목표·사용자·핵심 기능·화면 흐름·범위 밖·성공 기준 순서로 물어봐.
- 크기는 화면 1장, 핵심 기능 3개까지로 잡아 줘.
- 기록은 이 휴대폰 브라우저에만 저장하고, 로그인·여러 사람 공유·외부 서버는 범위 밖에 넣어 줘.
- 성공 기준은 휴대폰에서 직접 눌러 확인할 수 있는 문장 3개로 써 줘. 예) "운동을 추가하면 이번 주 합계가 바로 바뀐다"
- 내가 다 답하면 Markdown 형식의 PRD 한 장으로 정리해 줘. 파일 이름은 PRD.md
- 내가 말하지 않은 내용은 [확인 필요]로 표시해.
```

1. 질문에 편하게 답합니다. 모르면 "추천해 줘"라고 해도 됩니다.
2. 완성된 PRD에서 **[확인 필요]** 를 찾아 내 답으로 바꿔 달라고 하거나 직접 고칩니다.
3. 아래 표로 스스로 점검합니다. 하나라도 ❌이면 Claude에게 "○○를 고쳐 줘"라고 합니다.

| 점검 | 확인 |
|---|---|
| 핵심 기능이 **3개**인가? (4개 이상이면 나머지는 "다음에") | □ |
| **범위 밖**에 "로그인, 여러 사람 공유, 외부 서버"가 있나? | □ |
| **성공 기준 3개**가 휴대폰에서 눌러 볼 수 있는 문장인가? | □ |
| 실제 이름·연락처·주소가 없나? | □ |

4. PRD를 내려받아 **옵시디언**의 `01_기획(PRD)` 폴더에 `PRD.md`로 저장합니다 (다운로드 폴더에서 옮기기).

> 🧑‍🏫 1일차 05에서는 PRD 하나에 40분을 썼습니다. 오늘은 두 번째라 25분이면 충분합니다. 인터뷰가 길어지는 사람에게는 "지금까지 답한 것으로 PRD 정리해 줘"라고 끊게 합니다. **성공 기준이 흐릿하면 ⑥ 검토와 ⑧ 시험이 모두 흐려집니다.** 이 칸을 가장 꼼꼼히 봐 주세요.

## ③ PRD를 저장소에 올리기 (7교시, 5분)

PRD를 채팅창에 붙여넣는 대신 **저장소에 파일로** 올려 둡니다. 그러면 Claude Code가 언제든 다시 읽을 수 있고, PRD를 고친 기록도 남습니다. 설계도를 공사 현장 사무실 벽에 붙여 두는 것과 같습니다.

1. GitHub `my-tool` 저장소 → **[Add file] → [Upload files]**
2. 옵시디언 폴더의 `PRD.md` 를 끌어다 놓기
3. 아래 칸에 `내 관심사 PRD v1` 이라고 쓰고 **[Commit changes]**
4. 저장소 첫 화면에 `PRD.md` 가 보이면 완료. 눌러 보면 표와 제목이 보기 좋게 나옵니다.

## ④ 계획 먼저 받기 (8교시 시작, 10분)

바로 만들라고 하지 않고 **계획부터** 받습니다. 공사 전에 시공 계획서를 받아 보는 것과 같습니다. 계획 단계에서 잘못을 찾으면 고치는 데 1분이면 되지만, 다 만든 뒤에 찾으면 10분이 걸립니다.

`claude.ai/code` 에서 `my-tool` 을 고르고, 아래 [바로 해 보기]로 만든 지시문을 붙여넣습니다.

```
이 저장소의 PRD.md를 읽고, 이 PRD대로 휴대폰 화면을 만들 계획을 먼저 알려 줘. 아직 코드는 쓰지 마.

- 화면에 무엇이 위에서 아래로 놓이는지 그림처럼 적어 줘
- PRD의 핵심 기능 3개를 각각 어떻게 만들지 한 줄씩
- PRD에서 정하지 않아 네가 짐작해야 하는 것이 있으면 질문으로 3개까지
- 만들 파일은 index.html 하나, 기록은 이 브라우저(localStorage)에만, 외부 서버·외부 프로그램(라이브러리) 없이
```

1. Claude가 내놓은 **화면 그림**과 **기능 3줄**을 PRD와 비교합니다. PRD에 없는 기능이 끼어 있으면 "○○는 빼 줘"라고 합니다.
2. Claude의 **질문**에 답합니다. 답한 내용 중 중요한 것은 "이 답을 PRD.md에도 반영해 줘"라고 덧붙입니다.
3. 계획이 마음에 들면 ⑤로 갑니다. 이것이 **첫 번째 승인**입니다.

> 🧑‍🏫 "계획 먼저, 승인 뒤 만들기"는 AI 에이전트를 업무에 쓸 때 가장 중요한 습관입니다. 결재 문화로 비유하면 **기안 전에 방향 보고**를 받는 것입니다. Claude가 계획 없이 바로 만들기 시작하면 멈추게 하지 말고, 다 만든 뒤 ⑥에서 똑같이 검토하면 됩니다.

## ⑤ 만들기 v0.1 (8교시, 15분)

계획을 승인하고 만들게 합니다.

<div class="lab" data-lab="fill" data-tpl="cc-build"></div>

```
좋아, 그 계획대로 만들어 줘.

- 휴대폰 화면(폭 약 400px)에서 가로 스크롤 없이 보이게
- 처음 열었을 때 빈 화면이 아니도록 예시 기록 2~3개를 보여 주고, 예시는 지울 수 있게
- 화면 아래에 "기록은 이 브라우저에만 저장됩니다" 한 줄
- 다 만든 뒤 PRD.md의 성공 기준을 하나씩 직접 시험해 보고, 기준마다 통과 여부와 어떻게 시험했는지 표로 알려 줘
- 커밋 메시지는 한국어로 "(화면 이름) v0.1"
```

화면에 Claude가 하는 일이 차례로 나타납니다.

| 보이는 것 | 뜻 |
|---|---|
| 파일 만들기 (초록 줄) | 새로 쓴 코드 |
| 시험 실행 | 만든 화면이 PRD 성공 기준대로 동작하는지 스스로 확인 |
| 커밋·푸시 | 만든 것을 GitHub 창고에 저장. **세이브 포인트** |

- Claude Code는 원본(`main`)을 바로 고치지 않고 **연습장(브랜치)** 에 저장합니다. 내가 확인하고 **합치기** 전까지 실제 화면은 바뀌지 않습니다.
- 중간에 **허락을 묻는 화면**이 나오면 무엇을 하려는지 읽고 승인합니다. 모르는 내용이면 승인하지 말고 손을 들어 주세요.
- 기다리는 동안(3~10분) 옆 사람의 계획과 내 계획을 비교해 봅니다.

## ⑥ AI가 한 일 검토하기 (8교시, 10분) ⭐

코드를 한 줄씩 읽지 않아도 됩니다. **연습 → 표 → 질문** 순서로 확인합니다.

**연습 (3분):** 남이 만든 보고서에서 이상한 곳을 먼저 찾아봅니다.

## ⑦ 합치고 배포하기 (8교시, 15분)

**합치기 = 결재**
1. Claude Code 화면의 **[PR 만들기]**(Create PR)를 누릅니다.
2. GitHub 화면이 열리면 초록 버튼 **[Create pull request]** 가 보일 때 누릅니다 (이미 만들어진 경우는 건너뜀).
3. 초록 버튼 **[Merge pull request]** → **[Confirm merge]**
   - PR(풀 리퀘스트)은 "연습장의 내용을 원본에 합쳐도 될까요?"라는 **결재 요청서**입니다. 합치기를 누르는 것이 **결재**입니다.

**Netlify에 연결 (처음 한 번)**
1. `app.netlify.com` → **GitHub로 가입·로그인** (이미 GitHub에 로그인돼 있어 가장 빠릅니다)
2. **[Add new project]**(또는 Add new site) → **[Import an existing project]** → **GitHub**
3. 처음이면 GitHub에서 **Netlify에게 출입 권한을 주는** 화면(Install Netlify)이 나옵니다 → **Only select repositories** → `my-tool` **하나만** 선택 → **[Install]**. 이것도 PC에 까는 것이 아닙니다
4. 목록에서 `my-tool` → 설정은 **비워 둔 채** (Build command·Publish directory 모두 비움) → **[Deploy]**
5. **Project configuration → Change project name** 에서 주소 이름 바꾸기: 예) `run-log-hong` → `https://run-log-hong.netlify.app`

> ⚠️ **배포한 주소는 누구나 열 수 있습니다.** 저장소가 비공개여도 마찬가지입니다. 화면에 실제 이름·연락처·내부 자료가 없는지 한 번 더 봅니다.

> ⚠️ **Netlify 연결이 막히면:** GitHub `my-tool` 저장소에서 `index.html` 을 내려받아 `my-tool` 폴더에 넣고, `app.netlify.com/drop` 에 폴더째 끌어다 놓습니다. 주소는 바로 생기지만, ⑨부터는 고칠 때마다 다시 끌어다 놓아야 합니다.

## 마무리: 꾸준히 하면 업무 자동화까지

이틀 동안 사다리를 다섯 칸 올라왔습니다. 마지막 칸은 **정해진 때 저절로 돌아가게** 하는 것입니다.

```그림
① 잘 시키기      6하원칙 프롬프트                       (03)
② 자료 맡기기    프로젝트 · MD 파일                     (03 · 05)
③ 방법 맡기기    스킬 = 업무 매뉴얼                     (06)
④ 클릭 맡기기    AI 브라우저 · 루틴                     (08)
⑤ 내 도구 만들기 PRD → Claude Code → 검토 → 배포       (07 · 12)  ← 오늘 여기까지
⑥ 저절로 돌아가게 정해진 때 자동 실행, 여러 사람 자료 모으기  (다음 단계)
```

- 오늘은 관심사로 했지만 **순서는 업무에서도 똑같습니다.** PRD를 쓰고, 계획을 먼저 받고, 검토하고, 결재(합치기)하고, 써 보고 고칩니다.
- 한 번에 다 하지 않아도 됩니다. **일주일에 한 번, 30분**이면 됩니다.

| 주 | 사다리 | 해 볼 것 | 다 했으면 |
|---|---|---|---|
| 1주 | ①② 잘 시키기 · 자료 맡기기 | 내 업무 **프로젝트**를 만들어 규정·양식을 넣고, 업무 질문을 그 안에서 하기 | □ |
| 2주 | ③ 방법 맡기기 | **내 업무 스킬**을 실제 문서에 3번 쓰고, 고칠 점을 반영해 다시 올리기 | □ |
| 3주 | ④ 클릭 맡기기 | 매주 반복하는 웹 확인 작업 하나를 **AI 브라우저 루틴**으로 만들기 | □ |
| 4주 | ⑤ 내 도구 만들기 | 오늘 만든 관심사 화면을 **v0.3**으로 고치거나, 같은 순서로 **업무 화면** 하나를 PRD부터 만들어 동료 1명에게 써 보게 하기 | □ |

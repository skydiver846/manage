## AI에게 건네는 것의 단계

| 단계 | 무엇을 건네나 | 얼마나 오래 쓰나 | 비유 | 배운 곳 |
|---|---|---|---|---|
| 프롬프트 | 이번 지시 | 대화 한 번 | 구두 지시 | 모듈 3, 5 |
| 파일 건네기 | 참고 자료 | 대화 한 번 | 서류 첨부 | 모듈 3 |

| **스킬** | **일하는 방법 자체** | **어느 대화에서든. 필요할 때 AI가 알아서 꺼냄** | **업무 매뉴얼(SOP)** | **이번 모듈** |

## 6-1. 스킬은 어떻게 생겼나 (5분)

스킬은 **폴더 하나**입니다. 그 안에 `SKILL.md` 라는 Markdown 파일이 꼭 있어야 합니다.

```
📁 prd-interview          ← 스킬 폴더 (이름 = 스킬 이름)
 └─ 📄 SKILL.md           ← 필수. 이름, 언제 쓰는지, 일하는 순서
 └─ 📄 (참고 파일들)       ← 선택. 양식, 예시 문서 등
```

`SKILL.md` 는 두 부분으로 되어 있습니다.

```markdown
---
name: prd-interview
description: 사용자가 새 업무 도구를 기획하거나 "PRD 써 줘"라고 할 때 사용한다. ...
---

# PRD 인터뷰
1. 한 번에 질문은 1~2개만 한다.
2. ...
```

| 부분 | 무엇을 쓰나 | 규칙 |
|---|---|---|
| **위쪽 `---` 사이** (속성) | `name`: 스킬 이름 | **영문 소문자·숫자·하이픈(-)만** (GitHub Username 규칙과 비슷) |
| | `description`: 무엇을 하고 **언제** 쓰는지 | AI는 이 문장을 보고 스킬을 꺼낼지 판단합니다. **"언제"가 빠지면 스킬이 동작하지 않습니다** |
| **아래쪽 본문** | 일하는 순서, 양식, 지킬 것 | 모듈 4의 Markdown 그대로. 모듈 3의 프롬프트 공식(역할·목표·맥락·형식·조건)을 문서로 적은 것 |

> 🧑‍🏫 비유: 프롬프트가 **구두 지시**라면, 스킬은 **업무 매뉴얼을 책꽂이에 꽂아 두는 것**입니다. 표지(`description`)에 "언제 보는 매뉴얼인지"가 적혀 있어야 AI가 필요할 때 꺼내 봅니다.

## 6-2. 옵시디언에서 SKILL.md 쓰기 (10분)

1. 옵시디언 보관소에 **`98_스킬`** 폴더를 만들고, 그 안에 **`prd-interview`** 폴더를 만듭니다
2. `prd-interview` 폴더에서 **[새 노트]** → 제목을 정확히 **`SKILL`** (대문자)로
3. 실습 파일 [[실습자료/스킬/prd-interview/SKILL]] 의 내용을 붙여넣기
4. 맨 위 `---` 사이 부분이 옵시디언에서 **속성(Properties)** 상자로 보이면 정상입니다

```
📁 AI업무자료
 ├─ 📁 01_기획(PRD)
 ├─ 📁 02_참고자료
 ├─ 📁 03_AI결과물
 ├─ 📁 98_스킬
 │   └─ 📁 prd-interview
 │       └─ 📄 SKILL.md     ← 이번 모듈에서 만든 것
 └─ 📁 99_프롬프트
```

5. **Windows 파일 탐색기**에서 `문서 > AI업무자료 > 98_스킬 > prd-interview` 를 열어 파일 이름이 **`SKILL.md`** 인지 확인 (확장자 표시를 켜 두세요)

> 🧑‍🏫 읽으며 짚을 곳: 본문의 "한 번에 질문 1~2개", "[확인 필요]로 표시", "개인정보는 예시로" 같은 줄은 모듈 3·4에서 쓴 프롬프트와 같은 내용입니다. **매번 붙여넣던 프롬프트를 파일로 저장해 둔 것**이라는 점을 확인시켜 주세요.

## 6-3. Claude에 등록하고 써 보기 (10분)

### 스킬 등록

1. 파일 탐색기에서 **`prd-interview` 폴더**를 오른쪽 클릭 → **압축(ZIP)** 
   - Windows 11: **압축 대상 → ZIP 파일** / Windows 10: **보내기 → 압축(ZIP) 폴더**
   - ⚠️ 폴더 **안의** SKILL.md가 아니라 **폴더 자체**를 압축합니다
2. Claude 왼쪽 아래 프로필 → **설정** → **기능(Capabilities)** → **스킬(Skills)**
   - 코드 실행·파일 만들기 같은 기능을 먼저 켜야 스킬 메뉴가 보이는 경우가 있습니다
3. **[스킬 업로드]** → `prd-interview.zip` 선택 → 목록에서 **켜기**
4. **새 대화**에서 아무 설명 없이 입력:

```
교육 일정을 한눈에 관리하는 도구를 기획하고 싶어
```

5. Claude가 스킬을 꺼내 쓰면 화면에 스킬 사용 표시가 나오고, **"배경부터 여쭤볼게요"처럼 질문을 1~2개씩** 하기 시작합니다 ✅

> 🧑‍🏫 모듈 5에서는 긴 "PRD 인터뷰" 프롬프트를 붙여넣어야 했습니다. 스킬이 있으면 **한 문장**이면 됩니다. 모듈 5의 대화 화면과 지금 화면을 나란히 보여 주세요. "같은 인터뷰가 시작되는데, 내가 건넨 것은 한 문장뿐"이 이 모듈의 핵심 장면입니다.

### 참고: 무료 계정이라면 같은 파일을 다르게 건네기

| 방법 | 하는 법 |
|---|---|
| **프로젝트 지침으로** | 모듈 3에서 만든 프로젝트의 지침 칸에 SKILL.md 본문(아래쪽)을 붙여넣기 → 그 프로젝트 안에서 "기획하고 싶어" |
| **파일로 첨부** | 새 대화에 SKILL.md를 첨부하고 "이 파일의 방법대로 진행해 줘. 교육 일정 관리 도구를 기획하고 싶어" |

> 차이점: 스킬은 **어느 대화에서든 AI가 알아서** 꺼내고, 무료 방법은 **내가 건네야** 합니다. 그래도 매뉴얼을 파일로 한 번 써 두면 매번 다시 쓸 필요가 없다는 점은 같습니다.

## 6-4. Claude에게 스킬을 만들어 달라고 하기 (5분)

스킬도 AI와 함께 만들 수 있습니다.

```
과정이 끝날 때마다 쓰는 "강의평가 결과보고서"를 우리 양식으로 써 주는 스킬을 만들어 줘.
양식: 제목 / 1. 개요(과정·기간·응답률) / 2. 결과 요약(전체 평균) /
      3. 개선 필요 과목(평균 3.5 미만, 표) / 4. 주요 의견 / 5. 조치 계획(표)
- name은 eval-report, SKILL.md 하나로
- description에 "언제 쓰는지"를 꼭 넣어 줘
- 자료에 없는 숫자나 조치 일정은 [확인 필요]로 표시하게 해 줘
```

결과로 나온 SKILL.md는 옵시디언 `98_스킬/eval-report/` 에 저장합니다. 이 스킬은 모듈 7의 결재 보고서 실습과, 과정이 끝날 때마다 쓰는 실제 결과보고서에 그대로 쓸 수 있습니다.

> 🧑‍🏫 "기수마다 똑같은 양식으로 쓰는 보고서"가 스킬로 만들기 가장 좋은 일입니다. 교육생에게 내 업무의 **반복 보고서**를 하나씩 떠올리게 하세요.

## 6-5. 조직 배포: 문제출제 스킬 맛보기 (화면으로 함께 보기, 3분)

지금까지는 **내가 만든 스킬을 나만** 썼습니다. Team 계정에서는 관리자가 스킬을 **조직 전체에 배포**할 수 있습니다. 부서 공식 업무 매뉴얼을 한 번 나눠 주는 것과 같습니다.

| | 6-3 개인 등록 | 6-5 조직 배포 |
|---|---|---|
| 누가 올리나 | 나 | 관리자 한 명 |
| 누가 쓰나 | 나만 | **Team 멤버 전원** |
| 고칠 때 | 내가 다시 올림 | 관리자가 고치면 전원에게 반영 |

배포해 둔 스킬은 `quiz-generator` 입니다. 교재·법령을 주면 **객관식 문항 → 중앙소방학교 문제카드(hwpx) → 정답지**까지 만들어 줍니다. SKILL.md 한 장이 아니라 **양식 파일과 스크립트까지 든 폴더**라서, 스킬이 매뉴얼을 넘어 **업무 도구**까지 담을 수 있다는 것을 보여 줍니다.

1. 각자 설정 → 스킬 목록에 **quiz-generator** 가 보이는지만 확인
2. 실습 파일 **출제 의뢰서**와 **교재 발췌**를 내려받아 Claude 새 대화에 첨부하고 한 문장만 입력
```
첨부한 출제 의뢰서대로 교재 발췌를 범위로 문제카드를 만들어 줘
```
3. Claude가 **문항 수와 과정명·과목명·출제일자·소속·성명을 먼저 묻는 것**까지 봅니다. 수업에서는 앞 화면으로 함께 보고, 각자 직접 해 보는 것은 과제 ② 기간에 합니다(예시 값: 5문항, `교육운영팀`, `홍길동`).

> 🧑‍🏫 강사 준비 (D-10): Team 관리자 설정 → 스킬에서 `quiz-generator.zip` 을 **조직 전체**로 올리고, **코드 실행**이 켜져 있는지 확인합니다. 교육생 계정 하나로 목록에 보이는지, 실습 문장으로 hwpx가 나오는지 미리 한 번 해 보세요. 스킬 원본: `lecture/실습자료/스킬/quiz-generator/`
> 교재 발췌는 **실습용 자료**입니다. 실제 출제에는 공식 교범과 법령 원문을 쓰라고 짚어 주세요. 이 스킬의 핵심이 "근거 검증"인 이유입니다.

**더 해 보기 (수업 뒤): 문제카드 확인 기준**
```
□ 의뢰서대로 5문항, 난이도 상 1 · 중 3 · 하 1 인가?
□ 난이도 칸에 해당 값만 【 】 표시가 되어 있는가? (예: 상ㆍ【중】ㆍ하)
□ 출제근거가 교재의 어느 부분인지 적혀 있는가?
□ 교재에 없는 수치나 내용이 들어가지 않았는가?
□ 해설은 문제카드가 아니라 정답지에만 있는가?
```

## 6-6. 내 업무 스킬 만들기 (10분)

6-4와 같은 방법으로 **내 업무**의 스킬을 하나 만듭니다. 매번 같은 양식으로 쓰는 보고서, 안내문, 공문 초안이 가장 좋은 대상입니다.

```
내가 매번 같은 양식으로 쓰는 "[문서 이름]"을 우리 양식으로 써 주는 스킬을 만들어 줘.
양식: [제목 / 1. ○○ / 2. ○○ / 3. ○○ 처럼 내 양식의 칸을 적기]
- name은 영문 소문자와 하이픈으로 (예: weekly-report)
- description에 "언제 쓰는지"를 꼭 넣어 줘
- 자료에 없는 숫자나 날짜는 [확인 필요]로 표시하게 해 줘
```

1. 나온 SKILL.md를 옵시디언 `98_스킬/(name)/` 에 저장
2. 6-3과 같은 방법으로 Claude에 등록
3. 새 대화에서 **한 문장으로** 불러 보기: 예) `이번 주 주간 업무보고 써 줘`

> 🧑‍🏫 떠오르는 문서가 없는 교육생에게는 "지난달에 두 번 이상 쓴 문서"를 떠올리게 하세요. 실제 내용 대신 예시 내용으로 시험하게 합니다. 오늘 만든 스킬이 수업 뒤에 가장 오래 쓰일 결과물입니다.

## 좋은 스킬 체크리스트

```
□ description에 "무엇을"과 "언제"가 모두 있다
□ 스킬 하나에 일 하나 (PRD 인터뷰 + 보고서 작성을 한 스킬에 섞지 않기)
□ 순서가 번호로 적혀 있다
□ "지어내지 말 것([확인 필요])" 같은 지킬 것이 있다
□ 개인정보·비밀번호·내부 기밀이 들어 있지 않다
```

| `name` 오류 | 영문 소문자·숫자·하이픈만. 한글이나 띄어쓰기 불가 |
| 새 대화에서 스킬이 안 나옴 | 목록에서 스킬이 **켜짐**인지, `description` 에 "언제 쓰는지"가 있는지 확인. "PRD 인터뷰 스킬로 진행해 줘"라고 직접 불러도 됨 |
| 옵시디언에서 속성 상자가 안 보임 | 첫 줄이 정확히 `---` 인지 확인 (앞에 빈 줄이 있으면 안 됨) |

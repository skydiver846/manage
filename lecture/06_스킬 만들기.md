> 🧑‍🏫 ⚠️ **리허설 전 모듈입니다.** Claude의 스킬 등록 메뉴는 자주 바뀝니다. 강의 전에 Team 교육생 계정으로 한 번 해 보고 문구를 맞춰 주세요.

모듈 3에서 프롬프트, 파일, 프로젝트를 배웠고, 모듈 5에서는 PRD 인터뷰를 받으려고 **긴 프롬프트를 찾아 붙여넣었습니다.** 다음에 또 기획할 때도 그 글을 다시 찾아야 합니다.

이번 모듈은 그 불편을 없앱니다. **자주 하는 일의 "방법"을 Markdown 파일로 적어 AI에게 맡기는 것**, 이것이 스킬입니다. 첫 실습은 그 **PRD 인터뷰 프롬프트를 스킬로 만들어 둔 것**을 등록해 보는 것이고, 다음은 **Claude에게 스킬을 만들어 달라고** 해서 내 스킬까지 만듭니다. 직접 파일을 쓰지 않습니다.

> 🧑‍🏫 핵심 멘트: "**같은 지시를 세 번 이상 하고 있다면, 스킬로 만들 때입니다.**"
>
> 🧑‍🏫 시간 운영: 3교시에 내 PRD를 다 못 쓴 교육생이 많으면 **이 교시 처음 10분**을 PRD 마무리에 씁니다. 다 쓴 교육생은 그동안 내 PRD를 한 번 더 다듬습니다. 이 모듈은 40분이면 끝납니다.

## AI에게 건네는 것의 단계

| 단계 | 무엇을 건네나 | 얼마나 오래 쓰나 | 비유 | 배운 곳 |
|---|---|---|---|---|
| 프롬프트 | 이번 지시 | 대화 한 번 | 구두 지시 | 모듈 3, 5 |
| 파일 건네기 | 참고 자료 | 대화 한 번 | 서류 첨부 | 모듈 3 |
| 프로젝트(폴더) | 지침 + 자료 묶음 | 그 프로젝트 안에서 | 담당자 전용 서류함 | 모듈 3 |
| **스킬** | **일하는 방법 자체** | **어느 대화에서든. 필요할 때 AI가 알아서 꺼냄** | **업무 매뉴얼(SOP)** | **이번 모듈** |

## 6-1. 스킬은 어떻게 생겼나 (5분, 구조 보기 2분 + 맞춰 보기 3분)

스킬은 **폴더 하나**입니다. 그 안에 `SKILL.md` 라는 Markdown 파일이 꼭 있어야 합니다.

```
📁 prd-interview          ← 스킬 폴더 (이름 = 스킬 이름)
 └─ 📄 SKILL.md           ← 필수. 이름, 언제 쓰는지, 일하는 순서
```

`SKILL.md` 는 두 부분입니다.

```markdown
---
name: prd-interview
description: 사용자가 새 업무 도구를 기획하거나 "PRD 써 줘"라고 할 때 사용한다. ...
---

# PRD 인터뷰
1. 한 번에 질문은 1~2개만 한다.
2. ...
```

| 부분 | 무엇을 쓰나 |
|---|---|
| **위쪽 `---` 사이** | `name`: 스킬 이름 (영문 소문자·숫자·하이픈) · `description`: 무엇을 하고 **언제** 쓰는지 |
| **아래쪽 본문** | 일하는 순서, 양식, 지킬 것 (모듈 3의 프롬프트를 문서로 적은 것) |

> 💡 AI는 `description` 을 보고 스킬을 꺼낼지 판단합니다. **"언제"가 빠지면 스킬이 동작하지 않습니다.** 직접 쓸 필요는 없습니다. 6-3부터는 Claude가 써 줍니다.

<div class="lab" data-lab="skill"></div>

> 🧑‍🏫 비유: 프롬프트가 **구두 지시**라면, 스킬은 **업무 매뉴얼을 책꽂이에 꽂아 두는 것**입니다. 표지(`description`)에 "언제 보는 매뉴얼인지"가 적혀 있어야 AI가 필요할 때 꺼내 봅니다.

## 6-2. 만들어 둔 스킬 등록하고 써 보기 (10분)

모듈 5의 긴 **PRD 인터뷰 프롬프트**를 스킬로 만들어 두었습니다. 받아서 등록만 합니다.

1. **PRD 인터뷰 스킬 (ZIP)** 내려받기 (압축을 풀지 않습니다) → [[file:skill]]
2. Claude 왼쪽 아래 프로필 → **설정** → **기능(Capabilities)** → **스킬(Skills)**
   - 코드 실행·파일 만들기 같은 기능을 먼저 켜야 스킬 메뉴가 보이는 경우가 있습니다
3. **[스킬 업로드]** → `prd-interview.zip` 선택 → 목록에서 **켜기**
4. **새 대화**에서 아무 설명 없이 입력:

```
우리 가족 여행 준비를 한눈에 보는 도구를 기획하고 싶어
```

5. Claude가 스킬을 꺼내 쓰면 화면에 스킬 사용 표시가 나오고, **질문을 1~2개씩** 하기 시작합니다 ✅

> 🧑‍🏫 모듈 5에서는 긴 프롬프트를 붙여넣어야 했습니다. 스킬이 있으면 **한 문장**이면 됩니다. 모듈 5의 대화 화면과 지금 화면을 나란히 보여 주세요. "같은 인터뷰가 시작되는데, 내가 건넨 것은 한 문장뿐"이 이 모듈의 핵심 장면입니다.

## 6-3. Claude에게 스킬을 만들어 달라고 하기 (10분)

스킬도 AI가 만들어 줍니다. 여행 갈 때마다 다시 짜는 **여행 일정표**를 예로 해 봅니다.

```
여행 갈 때마다 쓰는 "여행 일정표"를 우리 집 양식으로 써 주는 스킬을 만들어 줘.
양식: 제목 / 1. 개요(인원·기간·이동) / 2. 날짜별 일정(표: 시간·장소·이동·메모) /
      3. 가족별 주의점 / 4. 준비물 / 5. 예산(표)
- name은 trip-plan
- description에 "언제 쓰는지"를 꼭 넣어 줘
- 입장료·운영시간처럼 확인하지 않은 요금과 시간은 [확인 필요]로 표시하게 해 줘
- 바로 올릴 수 있게 trip-plan 폴더째 ZIP 파일로 만들어 줘
```

1. Claude가 만든 **`trip-plan.zip`** 내려받기
2. 6-2와 같은 방법으로 **[스킬 업로드]** → 켜기
3. 새 대화에서 한 문장으로 불러 보기: `제주 2박 3일 우리 가족 여행 일정표 써 줘` → 같은 양식으로 나오고, 요금·운영시간 자리에 **[확인 필요]** 가 표시되면 정상

경주에서 만든 스킬을 제주에도 그대로 씁니다. 양식이 같으면 장소만 바꿔 한 문장으로 부르면 됩니다. 이 스킬은 모듈 7의 **가족 단톡방용 여행 안내 한 장** 실습에도 쓸 수 있습니다.

> 🧑‍🏫 ZIP 파일이 나오지 않으면 "trip-plan 폴더 안에 SKILL.md를 넣어 ZIP으로 내려받게 해 줘"라고 한 번 더 시킵니다. 그래도 안 되면 SKILL.md 내용을 복사해 아래 "참고" 방법(프로젝트 지침)으로 씁니다.
>
> 🧑‍🏫 [확인 필요] 대신 그럴듯한 요금·시간이 나오면 좋은 시연 소재입니다. "이 숫자는 어디서 왔나요?"라고 물어 보게 하고, 스킬 본문에 "확인하지 않은 요금·시간은 쓰지 말 것"이 있는지 함께 봅니다.

## 6-4. 내 스킬 만들기 (15분)

6-3과 같은 방법으로 **내 스킬**을 하나 만듭니다. 매번 같은 양식으로 쓰는 글이 가장 좋은 대상입니다. 업무 문서(주간보고, 안내문, 공문 초안)도 좋고, 일상 양식(가족 행사 안내, 주간 식단표)도 좋습니다.

아래 [바로 해 보기]에서 예시를 고르거나 칸을 내 문서로 바꾼 뒤 **[프롬프트 복사]** → Claude 새 대화에 붙여넣습니다. 칸 채우기가 낯설면 그 아래 **원본**을 복사해 `[ ]` 자리만 바꿔도 됩니다.

<div class="lab" data-lab="fill" data-tpl="skill"></div>

```
내가 매번 같은 양식으로 쓰는 "[문서 이름]"을 내 양식으로 써 주는 스킬을 만들어 줘.
양식: [제목 / 1. ○○ / 2. ○○ / 3. ○○ 처럼 내 양식의 칸을 적기]
- name은 영문 소문자와 하이픈으로 (예: weekly-report, family-event, weekly-menu)
- description에 "언제 쓰는지"를 꼭 넣어 줘
- 자료에 없는 숫자나 날짜는 [확인 필요]로 표시하게 해 줘
- 바로 올릴 수 있게 폴더째 ZIP 파일로 만들어 줘
```

1. ZIP 내려받기 → **[스킬 업로드]** → 켜기
2. 새 대화에서 **한 문장으로** 불러 보기: 예) `이번 주 주간 업무보고 써 줘`, `할머니 생신 가족 모임 안내 써 줘`, `다음 주 식단표 짜 줘`
3. (보관) ZIP 파일을 내 업무 폴더 `98_스킬` 에 넣어 둡니다. 나중에 고칠 때 씁니다.

> 🧑‍🏫 떠오르는 문서가 없는 교육생에게는 "지난달에 두 번 이상 쓴 글"을 떠올리게 하세요. 업무 문서가 기밀 때문에 어렵다면 일상 양식으로 해도 됩니다. 실제 내용 대신 예시 내용으로 시험하게 합니다. 오늘 만든 스킬이 수업 뒤에 가장 오래 쓰일 결과물입니다.

### 참고: 무료 계정이라면 같은 파일을 다르게 건네기

| 방법 | 하는 법 |
|---|---|
| **프로젝트 지침으로** | 모듈 3에서 만든 프로젝트의 지침 칸에 SKILL.md 본문(아래쪽)을 붙여넣기 → 그 프로젝트 안에서 한 문장으로 요청 |
| **파일로 첨부** | 새 대화에 SKILL.md를 첨부하고 "이 파일의 방법대로 진행해 줘" |

> 차이점: 스킬은 **어느 대화에서든 AI가 알아서** 꺼내고, 무료 방법은 **내가 건네야** 합니다.

## 좋은 스킬 체크리스트

```
□ description에 "무엇을"과 "언제"가 모두 있다
□ 스킬 하나에 일 하나 (PRD 인터뷰 + 일정표 작성을 한 스킬에 섞지 않기)
□ 순서가 번호로 적혀 있다
□ "지어내지 말 것([확인 필요])" 같은 지킬 것이 있다
□ 개인정보·비밀번호·내부 기밀이 들어 있지 않다
```

## 자주 막히는 곳

| 상황 | 해결 |
|---|---|
| 설정에 스킬 메뉴가 없음 | Team 화면이 맞는지(왼쪽 아래 Team 이름) 확인 → 맞으면 관리자 설정에서 스킬이 꺼져 있는 것. 당장은 "참고" 방법(프로젝트 지침·첨부)으로 진행 |
| 업로드하면 형식 오류 | ZIP 안에 **폴더째** 들어 있는지, 파일 이름이 정확히 `SKILL.md` 인지 확인. 안 되면 Claude에게 "업로드 형식 오류가 나. 다시 만들어 줘" |

| 새 대화에서 스킬이 안 나옴 | 목록에서 스킬이 **켜짐**인지, `description` 에 "언제 쓰는지"가 있는지 확인. "PRD 인터뷰 스킬로 진행해 줘", "trip-plan 스킬로 써 줘"처럼 직접 불러도 됨 |
| 일정표에 요금·운영시간이 숫자로 나옴 | 자료 없이 AI가 지어낸 것일 수 있음. "확인하지 않은 요금·시간은 [확인 필요]로 바꿔 줘"라고 시키고, 스킬 본문에도 이 규칙을 넣어 달라고 하기 |

## ✅ 확인 질문 (인터뷰)

1. 프롬프트, 프로젝트, 스킬의 차이를 한 줄씩 말해 볼까요? (구두 지시 / 서류함 / 업무 매뉴얼)
2. `description` 에 **"언제"** 를 꼭 써야 하는 이유는? (정답: AI가 그 문장을 보고 스킬을 꺼낼지 판단하므로)
3. `trip-plan` 일정표에서 요금·운영시간 자리에 **[확인 필요]** 가 나와야 하는 이유는? (정답: 자료에 없는 정보를 AI가 지어내지 않게, 공식 누리집에서 직접 확인하려고)
4. 업무든 일상이든 **세 번 이상 같은 지시를 한 일**은 무엇인가요? 그것이 다음 스킬 후보입니다.

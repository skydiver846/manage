## 한 장의 PRD, 여러 개의 결과물

```
                              ┌─▶ Gemini Notebook ─▶ 요약 · 오디오 해설 · 슬라이드 · 인포그래픽
 📄 PRD.md + 여행 자료 (내 폴더) ─┴─▶ Claude     ─▶ 단톡방 여행 안내 · 일정표 · 프로토타입(웹 화면)
```

| 도구 | 성격 | 이럴 때 |
|---|---|---|
| **Gemini Notebook** | **내가 넣은 자료 안에서만** 답하는 AI 연구 노트 | 자료를 이해하고 요약·학습할 때 |
| **Claude** (ChatGPT도 같은 성격) | 일반 지식 + 내 자료를 섞어 **새로 만드는** AI | 문서·화면 등을 새로 만들 때 |

## 7-1. Gemini Notebook (약 15분: 넣고, 누르고, 기다리지 않기)

> ⏱️ 이 교시의 주인공은 7-3 **내 화면 시안**입니다. 수업에서는 Gemini Notebook으로 **세 가지만** 합니다: ① 소스 3개 넣기 → ② 오디오 개요·슬라이드 **[생성]** 누르기 → ③ 채팅 질문 1개. 오디오·슬라이드는 만들어지는 데 몇 분씩 걸리니, 기다리지 말고 7-2로 넘어갑니다. 결과는 교시 끝이나 **과정 뒤에** 열어 봅니다.
>
> 제목에 **(과정 뒤)** 가 붙은 마인드맵·인포그래픽·PRD 검토(불일치 찾기, v0.3)는 과정 뒤에 해 봅니다.

> 💡 **이름이 바뀌었습니다.** 2026년 7월부터 **NotebookLM** 의 새 이름이 **Gemini Notebook** 입니다. 기능과 만들어 둔 노트북은 그대로입니다. 인터넷 검색이나 예전 자료에서는 NotebookLM이라는 이름도 계속 보입니다.

### 시작하기
1. "업무" Chrome 프로필 창에서 `notebooklm.google.com` 접속
2. Google 계정으로 로그인 (별도 가입 없음)
3. **[새 노트북 만들기]** (또는 Create new)

### 소스(자료) 넣기
1. **소스 추가** 창에서 **파일 업로드** 선택
2. 내 폴더 `문서 > AI업무자료 > 01_기획(PRD)` 의 **`PRD_경주 여행 준비물.md`** 선택 (모듈 5에서 고친 파일. 없으면 [[실습자료/PRD_경주 여행 준비물]] 을 받아서)
3. `02_참고자료` 의 **`경주 여행 자료_관광지 안내.md`** 와 **`경주 여행 후기_예시.md`** 도 함께 추가 (없으면 [[실습자료/경주 여행 자료_관광지 안내]], [[실습자료/경주 여행 후기_예시]] 를 받아서)
4. 그 밖에 함께 참고할 자료가 있으면 추가 (PDF, 텍스트, 웹사이트 주소, YouTube 링크, Google 문서 등)

> 💡 **MD 파일을 바로 올릴 수 있다는 것**이 Gemini Notebook의 장점입니다. 형식 변환 없이 PRD.md 파일을 그대로 넣습니다.

### 해 볼 것

| 기능 | 하는 법 | 결과 |
|---|---|---|
| **질문하기** | 가운데 채팅창에 질문 | 답 옆에 **출처 번호**가 붙어 원문 위치 확인 가능 |
| **오디오 개요** | 스튜디오 영역의 오디오 개요 생성 (아래 지시문) | 두 사람이 자료를 대화로 들려주는 **팟캐스트형 음성**. 이번에는 **차에서 아이와 듣는 경주 라디오** |
| **마인드맵** (과정 뒤) | 마인드맵 생성 | 장소·준비물 구조를 한눈에 보는 그림 |
| **슬라이드** · 인포그래픽 (과정 뒤) | 스튜디오에서 생성 (아래 7-1-1) | 가족과 나눠 볼 여행 소개 자료와 한 장 요약 그림 |
| 보고서·학습 가이드 (과정 뒤) | 보고서 메뉴에서 형식 선택 | 브리핑 문서, 학습 가이드, FAQ 등 |

오디오 개요의 **연필(맞춤 설정)** 아이콘을 누르고 아래처럼 적어 두면, 가는 길 차 안에서 아이와 들을 수 있는 해설이 됩니다.

```
초등학교 3학년 아이가 경주 가는 차 안에서 듣는 라디오처럼 만들어 줘.
첨성대, 동궁과 월지, 국립경주박물관 이야기를 쉬운 말로, 퀴즈를 섞어서.
소스에 없는 요금이나 운영시간은 말하지 마.
```

> 메뉴 이름과 위치는 업데이트로 바뀔 수 있습니다. 오디오 개요는 생성에 몇 분 걸리고, 출력 언어 설정을 한국어로 확인하세요.

### 7-1-1. 슬라이드와 인포그래픽 만들기 (생성 버튼만 누르고 넘어가기)

같은 자료(PRD + 관광지 안내 + 후기)로 **가족과 나눠 볼 여행 소개 자료(슬라이드)** 와 **한 장짜리 요약 그림(인포그래픽)** 을 만듭니다. Gemini Notebook은 **넣은 자료(소스)만** 근거로 만들기 때문에, 자료에 없는 요금·시간이 끼어들 가능성이 적습니다.

**① 슬라이드 (Slide Deck)**

1. 오른쪽 **스튜디오** → **슬라이드(Slide Deck)** 옆의 **연필(맞춤 설정)** 아이콘
2. 설정 고르기

| 항목 | 고를 것 | 뜻 |
|---|---|---|
| 형식 | **자세한 자료(Detailed Deck)** | 단톡방에 올려 각자 읽는 자료. 모여서 말로 설명할 거면 **발표자용 슬라이드(Presenter Slides)** |
| 언어 | **한국어** | |
| 길이 | 짧게 | 휴대폰으로 볼 자료는 짧을수록 좋음 |
| 프롬프트 | 아래 지시문 | 누구에게, 몇 장, 무엇을 강조할지 |

```
우리 가족(나, 배우자, 초등 3학년 아이, 75세 할머니)에게 경주 2박 3일 여행을 소개하는 5장짜리 자료로 만들어 줘.
1장: 여행 한눈에 보기(언제, 어디, 숙소), 2장: 할머니가 걷기 편한 곳, 3장: 아이가 좋아할 곳,
4장: 비 오는 날 바꿀 곳, 5장: 각자 챙길 준비물.
소스에 없는 요금·운영시간은 쓰지 마.
```

3. **[생성]** → 기다리지 말고 넘어가기 (오디오 개요와 함께 눌러 두면 시간을 아낄 수 있음)
4. (과정 뒤) **고치기**: 고치고 싶은 장을 열고 **연필** 아이콘 → "3장 글자를 더 줄여 줘"처럼 **말로** 고칩니다
5. (과정 뒤) **내려받기**: **⋮** → **PDF** 또는 **PowerPoint(.pptx)**. PPTX는 PowerPoint에서 글자를 직접 고칠 수 있습니다

**② 인포그래픽 (Infographic) (과정 뒤)**

1. 스튜디오 → **인포그래픽** 옆 **연필** 아이콘
2. **방향**(가로 / 세로 / 정사각형), **언어: 한국어**, 프롬프트 입력

```
경주에서 가 볼 만한 곳을 "할머니가 걷기 편한 곳 / 아이가 좋아할 곳 / 비 오는 날 갈 곳"
세 묶음으로 나눈 한 장 그림으로 만들어 줘.
아래에는 꼭 챙길 준비물 3개(할머니 혈압약, 아이 멀미약, 얇은 겉옷)를 넣어 줘.
가을 단풍색을 강조색으로, 글자는 크게. 요금·시간은 넣지 마.
```

3. **[생성]** → 완성되면 이미지로 저장

**③ 결과 검토 (과정 뒤, 결과가 나오면 꼭 하기)**

```
□ 자료에 없는 요금·운영시간·장소가 들어가지 않았나?
□ 그림 속 한글에 오타나 깨진 글자가 없나? (그림으로 그린 글자라 틀릴 수 있음)
□ 할머니가 어려운 곳(계단·오르막)이 "걷기 편한 곳"에 들어가 있지 않나?
□ 개인정보(가족 실명·연락처·사진)가 보이지 않나? (단톡방 밖으로 퍼질 수 있음)
```

> 💡 7-2의 Claude "단톡방 안내 한 장"과 비교해 보세요. Claude는 **바로 고칠 수 있는 글**을 주고, Gemini Notebook은 **완성된 슬라이드·그림**을 줍니다. 글로 내용을 정리하고, 슬라이드·그림으로 한눈에 보여 주는 식으로 함께 쓰면 좋습니다.
>
> 내려받은 PDF·PPTX·이미지는 내 폴더 `03_AI결과물` 에 함께 보관합니다.

> 🧑‍🏫 슬라이드·인포그래픽은 **만 18세 이상** 계정에서 무료로 쓸 수 있고, 생성에 수 분이 걸리며 하루 생성 횟수에 한도가 있을 수 있습니다. 강의 직전에 교육생과 같은 무료 계정으로 메뉴 이름과 한도를 확인하고, 생성이 늦어질 때를 대비해 미리 만든 예시 PDF를 준비해 두세요. 행정망에서 PPTX 내려받기가 막히면 PDF로 받습니다.

### 실습 질문 (Gemini Notebook 채팅창, 수업에서는 1개)

```
관광지 안내와 후기를 바탕으로, 무릎이 불편한 할머니와 초등 3학년 아이가
함께 가기 좋은 곳과 피하면 좋을 곳을 표로 정리해 줘. 이유도 함께 적어 줘.
```

**볼 것:** 답 옆의 **출처 번호** [1], [2] 를 눌러 관광지 안내·후기·PRD의 어느 문장을 근거로 했는지 확인합니다 (ChatGPT·Claude와 가장 다른 점).

(과정 뒤) 더 물어볼 것:

```
둘째 날 비가 오면 어디로 바꾸면 좋을까? 자료에 있는 장소로만 답해 줘.
```

> 💡 Gemini Notebook은 **자료에 없는 것을 잘 지어내지 않습니다.** 요금을 물으면 "자료에 없다"고 답하는지 보세요.

### PRD 검토 · 불일치 찾기 → v0.3 (과정 뒤)

"서로 맞는지·빠진 것 찾기"를 시키면 Gemini Notebook을 **PRD 검토 도구**로 쓸 수 있습니다.

```
PRD의 배경, 핵심 기능, 화면·흐름, 성공 기준이 서로 맞는지 비교해 줘.
배경에 적힌 내용 중 기능에 빠진 것이 있으면 알려 줘.
```

**볼 것: 불일치 찾기**

PRD v0.1 그대로라면 1번 배경("가족마다 챙길 것이 다르다")과 4번 기능(준비물을 한 목록으로만 셈)이 어긋납니다. 모듈 5에서 4번 칸만 "누구 것 + 가족별 집계"로 고쳤다면, 5번 화면 흐름은 아직 "준비물 [____] [추가]"만 있고 누구 것을 고르는 칸이 없습니다. 7번 성공 기준에도 "가족 전체로는 순조로워도 덜 챙긴 사람은 따로 '서둘러요'" 같은 문장이 없습니다. Gemini Notebook이 이 불일치를 짚어 주면 Claude에게 5·7번 칸을 고치게 하고 **v0.3** 으로 올립니다.

```
 PRD 파일 수정 ─▶ Gemini Notebook에 다시 넣어 검토 ─▶ 불일치 발견 ─▶ 다시 수정
```

> ⚠️ Gemini Notebook에 올린 파일은 **복사본**입니다. 내 PC에서 PRD를 고쳐도 Gemini Notebook 안의 파일은 바뀌지 않으니, 다시 검토하려면 **기존 소스를 지우고 새로 업로드**합니다. 가장 많이 헷갈리는 부분입니다.
>
> AI가 불일치를 못 찾으면 "4번과 5번 칸의 입력 항목이 서로 같은지 비교해 줘"처럼 **구체적으로** 다시 물어보세요.

> 🧑‍🏫 오디오 개요는 생성에 **수 분**이 걸립니다. 버튼을 먼저 눌러 두고 7-2(Claude)를 진행한 뒤, 완성되면 강의장 스피커로 **30초만** 들려 주세요. "차에서 아이와 듣는 라디오"라는 말에 반응이 좋습니다. 생성이 늦어질 때를 대비해 미리 하나 만들어 두면 좋습니다.

## 7-2. Claude로 가족 단톡방용 여행 안내 한 장 만들기 (약 10분)

`경주 여행 자료_관광지 안내.md` 와 `경주 여행 후기_예시.md` 를 첨부(또는 모듈 3의 "우리 가족 여행" 프로젝트에 추가)한 뒤:

**① 단톡방용 여행 안내 한 장**
```
첨부한 관광지 안내와 후기를 바탕으로 가족 단톡방에 올릴 경주 2박 3일 여행 안내를 한 장으로 써 줘.
형식: 제목 / 한 줄 요약 / 날짜별 일정(표: 시간·장소·이동·메모) / 각자 챙길 것 / 비 오면 / 출발 시각과 모이는 곳.
할머니는 오래 걷기와 계단이 어렵고, 아이는 차멀미가 있어. 휴대폰으로 읽기 쉽게 짧게.
자료에 없는 요금·운영시간은 만들지 말고 [확인 필요]로 표시해.
```

> 💡 모듈 6-3에서 `trip-plan`(여행 일정표) 스킬을 만들었다면 자료를 첨부하고 "경주 2박 3일 우리 가족 여행 일정표 써 줘" 한 문장으로 **일정표 자체**를 먼저 받아 보세요. 그다음 "이걸 단톡방용 한 장으로 줄여 줘"라고 이어 가면 됩니다. 요금·운영시간이 [확인 필요]로 나오는 것이 정상입니다. 실제 여행 전에는 공식 누리집에서 확인합니다.

> 💼 **업무에서는** 같은 방법으로 결재 보고서를 만듭니다. PRD나 자료를 첨부하고 형식만 "제목 / 추진 배경 / 주요 내용 / 기대 효과 / 향후 일정"으로 바꾸면 됩니다.

**② 비 오는 날 버전 (시간이 남으면)**
```
같은 안내를 둘째 날 비가 오는 경우로 바꿔 줘.
실내 장소로만 바꾸고, 바뀐 부분은 굵게 표시해 줘.
```

## 7-3. 내 PRD로 내 화면 시안 만들기 (약 20분) ⭐

오늘 3교시에 쓴 **내 PRD**를 Claude에 건네, 처음으로 **내 화면**을 봅니다. 내일 오전(모듈 12)에 웹 주소가 있는 진짜 화면으로 만들 그 화면입니다.

```
첨부한 PRD를 읽고, 핵심 기능(필수)만 동작하는 프로토타입 웹 화면을 만들어 줘.
- HTML 파일 하나로, 설치 없이 브라우저에서 바로 열리게
- 휴대폰 화면에서도 보기 좋게
- "범위 밖" 기능은 넣지 마
- 처음 열었을 때 예시 데이터 3개를 보여 줘
```

1. 내 폴더 `01_기획(PRD)` 의 **내 PRD 파일**을 첨부하고 위 지시를 보냅니다.
2. 대화 옆 **미리보기 창**에서 내 화면을 눌러 봅니다.
3. 마음에 들지 않는 부분은 대화로 고칩니다: "버튼을 더 크게", "입력칸 순서를 바꿔 줘"
4. **바꾸고 싶은 점 3가지**를 메모해 둡니다. 2일차 8교시를 시작할 때 PRD에 반영합니다.

- **내 PRD가 아직 덜 됐다면** 예시 [[실습자료/PRD_경주 여행 준비물]] (모듈 5에서 누구 것 구분을 넣어 고친 파일)로 같은 실습을 합니다(아래 성공 기준 표가 이 준비물 화면 기준입니다).
- 미리보기 창이 **빈 화면**이면: 미리보기는 `claudeusercontent.com` 이라는 별도 주소에서 그려지는데, 행정망에서 이 주소가 막혔을 수 있습니다. 코드를 복사해 메모장에 `index.html`(UTF-8)로 저장하고 Chrome에서 열면 똑같이 동작합니다.
- 답이 중간에 끊기면 **"계속해 줘"** 라고 입력합니다. 사용량 한도 안내가 뜨면 ChatGPT에 같은 지시를 넣어 진행합니다(ChatGPT는 캔버스에서 미리보기).

> 예시 결과물: 실습 파일의 **준비물 체크 화면**(`index.html`, 모듈 09·10에서 씁니다)이 예시 PRD를 고친 v0.3으로 만든 화면입니다. 생성이 늦어지면 이 화면을 먼저 보며 따라 합니다.

> 🧑‍🏫 이 20분이 1일차의 하이라이트입니다(7-1에서 아낀 10분을 여기에 씁니다). "3교시에 말로 정리한 내 아이디어가 지금 화면이 됐습니다." 서로 화면을 돌려 보게 하면 반응이 좋습니다. 내 PRD로 한 사람은 성공 기준 점검을 **자기 PRD 7번**으로 합니다. 생성이 늦어지는 교육생을 위해 예시 결과물을 화면에 띄워 두세요.

### PRD의 성공 기준으로 검사하기

미리보기 화면에서 PRD 7번 칸을 그대로 시험해 봅니다. **내 PRD**로 했다면 내 7번 문장을 하나씩, **예시 PRD**로 했다면 아래 표대로 해 봅니다.

| 성공 기준 | 해 보기 | 결과 |
|---|---|---|
| 준비물 이름과 누구 것을 골라 추가된다 | `혈압약`, 누구 것 `할머니` → [추가] | ☐ |
| 챙김률 50% 미만이면 "서둘러요"로 표시된다 | 누구 것 `아이`로 `멀미약`, `여벌 옷`, `물놀이 가방` 추가 → `물놀이 가방`만 체크 (3개 중 1개, 33%) | ☐ |
| 준비물 이름이 비어 있으면 막힌다 | 준비물 칸을 비우고 [추가] | ☐ |
| **가족 전체로는 순조로워도, 덜 챙긴 사람은 따로 "서둘러요"로 보인다** | 할머니 것 `무릎 보호대`·`지팡이`, 가족 전체 `충전기`·`우산`을 더 추가하고, 할머니 것 3개(`혈압약` 포함)와 가족 전체 2개를 모두 체크 → 요약은 8개 중 6개 챙김(75%)인데 가족별 표에서 **아이 줄만** "서둘러요"인지 | ☐ |

> 💡 처음 보이는 "(예시)" 준비물이 섞이면 숫자는 조금 달라도 됩니다. **아이 줄이 따로 "서둘러요"로 보이는지**만 확인하세요.

> 🧑‍🏫 핵심 멘트: "모듈 3에서 AI가 찾은 구멍, 모듈 5에서 우리가 고친 규칙이 지금 **화면에서 그대로 동작**합니다. PRD에 적었기 때문입니다." 화이트보드의 숫자(할머니 100%, 아이 33%, 한 목록이면 75% "순조로움")를 다시 가리키면 좋습니다.
>
> 화면에서 바꾼 규칙(예: "서둘러요" 기준을 80%로)은 **PRD에도 반영**합니다. 기준 문서는 언제나 PRD입니다.
>
> 이 화면의 기록은 **각자의 브라우저에만** 저장됩니다. "가족이 각자 휴대폰으로 체크하면 서로 보여야 하지 않나요?"라는 질문이 나오면 2일차 배포(10)에서 직접 확인한다고 연결하세요.

# 생성형 AI 업무 활용 입문 — 강의 개요

> 대상: 컴퓨터는 쓰지만 AI 도구·옵시디언·GitHub 계정이 **하나도 없는** 처음 시작하는 분
> 환경: Windows + Chrome 브라우저
> 진행 방식: 강사가 단계마다 **확인 질문(인터뷰)** 을 던지고, 모두 "완료"하면 다음 단계로

---

## 강의 목표

수업이 끝나면 교육생은 다음을 **혼자서** 할 수 있습니다.

1. 용도별 Google 계정을 만들고 Chrome에서 바꿔 가며 쓴다
2. ChatGPT와 Claude에 가입하고, 좋은 프롬프트로 원하는 답을 얻는다
3. AI에 **파일을 건네고**, **프로젝트(폴더)** 로 자료를 묶어 반복 작업을 줄인다
4. 자주 하는 일의 방법을 MD 파일(**SKILL.md**)로 적어 **스킬**로 AI에게 맡긴다
5. 옵시디언에서 MD 파일로 **PRD(기획서)** 를 쓴다
6. 그 PRD를 Gemini Notebook·ChatGPT·Claude에 넣어 **요약, 발표자료, 오디오 해설, 프로토타입**을 만든다

## 실습 주제: 과정별 강의평가 결과보고

모든 모듈이 **하나의 행정 업무**를 처음부터 끝까지 자동화하는 흐름으로 이어집니다. 과정이 끝날 때마다 종이 설문을 엑셀에 옮기고, 과목별 평균을 내고, 결과보고서를 쓰는 일입니다.

| 단계 | 지금 (손으로) | 이 강의에서 (AI와 함께) | 모듈 |
|---|---|---|---|
| 참여 요청 | 안내문 직접 작성 | 5요소 프롬프트로 안내문 | 03 |
| 자유의견 정리 | 한 장씩 읽고 요약 | 파일을 건네 과목별 요약 | 03 · 07 |
| 집계 도구 기획 | 없음 | PRD 작성, AI가 구멍(교관 구분) 찾기 | 03 · 06 |
| 결과보고서 | 매 기수 같은 양식을 새로 | 스킬(`eval-report`)로 양식 고정 | 05 · 07 |
| 보고 자료 | 직접 PPT 제작 | Gemini Notebook 슬라이드·인포그래픽 | 07 |
| 집계 | 엑셀에 옮겨 평균 계산 (반나절) | 평가 화면이 자동 집계, 3.5 미만 "개선 필요" | 07 · 08 |
| 응답 모으기 | 종이 회수 | 웹 주소(배포) + 공용 장부(Firebase) | 09 · 10 |
| 결과표 내려받기 | 표를 손으로 옮김 | Claude Code가 기능 추가 | 11 |
| 응답 현황 확인 | 매일 열어 보기 | Aside 루틴이 매일 확인 | 12 |

> 🧑‍🏫 교육생 각자의 업무로 바꿔 보는 연습은 모듈 6의 "내 PRD 쓰기"에서 합니다. 예시 주제를 따라가며 방법을 익히고, 같은 방법을 내 업무에 적용합니다.

## 강의장 환경: 행정망 데스크톱

이번 강의는 **행정망에 연결된 강의장 데스크톱 PC**에서 진행합니다.

| 항목 | 리허설 결과 | 수업 전 할 일 |
|---|---|---|
| GitHub · Vercel 배포 (모듈 09) | ✅ 행정망 리허설에서 배포까지 확인 | 없음 |
| Firebase (모듈 10) | ❓ 아직 확인 전 | **접속 점검 페이지**로 확인 → A안(교육생 실습) 또는 B안(강사 시연) 결정 |
| ChatGPT · Claude · Gemini Notebook (모듈 02~07) | 점검 필요 | 접속 점검 페이지로 확인. 막혀 있으면 전산 담당자에게 강의 시간 동안 접속 허용 요청 |
| 옵시디언 설치 (모듈 04) | 점검 필요 | 기관 PC는 프로그램 설치가 막혀 있을 수 있음. 막히면 전산 담당자에게 사전 설치 요청, 안 되면 메모장으로 진행 |

**접속 점검 페이지**: 저장소 `prototype-demo/network-check.html`
- 강의장 PC의 Chrome에서 열면 강의에 쓰는 사이트(Google, ChatGPT, Claude, Gemini Notebook, 옵시디언, GitHub, Vercel, Firebase)가 열리는지 자동으로 보여 줍니다.
- 2단계에서 Firebase 설정값을 붙여넣으면 **공용 장부에 실제로 접속되는지**까지 시험하고, 모듈 10를 A안으로 할지 B안으로 할지 판정해 줍니다.
- 열기 쉬운 방법: `fire-ai-classroom` 저장소에 올려 두었으므로 `(Domains 주소)/network-check.html` 로 열면 됩니다(행정망에서 Vercel이 열리는 것을 확인했으므로).

## 교육생용 강의 사이트

교육생 PC에는 **교육생용 강의 사이트**를 띄워 진행합니다. 강의 플랫폼에는 이 사이트 주소 하나만 링크합니다.

- 만드는 곳: `tools/classroom` (이 강의자료로 자동 생성) → 결과물 `classroom-site/`
- 배포: GitHub `skydiver846/fire-ai-classroom` 저장소의 `fire-ai/` 폴더 → Vercel. 교육생 주소는 `(Domains 주소)/fire-ai/` (방법은 `tools/classroom/README.md`)
- 교육생판에는 강사 노트·정답·강사용 파일이 빠지고, 사이트 주소는 클릭 링크로, 프롬프트에는 [복사] 버튼이, 모듈마다 실습 파일 [내려받기] 버튼이 붙습니다.
- 강의자료를 고치면 `npm run build` 로 다시 만들어 저장소에 다시 올립니다.

## 자료 배포: 데스크톱이므로 QR보다 링크

QR은 휴대폰 카메라로 찍는 것이라 **데스크톱 PC로는 자료를 받을 수 없습니다.**

| 용도 | 방법 |
|---|---|
| 강의자료·실습 파일 배포 | **짧은 주소를 화면에 띄워 직접 입력**하거나, PC 메신저·메일로 **링크 공유**. 인터넷이 불안하면 실습 파일을 강의장 PC 바탕화면에 미리 복사 |
| 배포한 강의평가 화면에서 평가해 보기 (모듈 09·10) | **QR 사용**: 교육생 본인 휴대폰(LTE)으로 열어 보기 |

## 계정 트랙: 무료 / Pro (교육생 계정은 강의 직전에 결정)

교육생 Claude 계정이 Pro가 될 가능성이 높지만 무료로 갈 수도 있으므로, **자료는 두 경우 모두 그대로 쓰도록** 짜 두었습니다.

- **모듈 00~10은 무료 계정으로 끝까지 되는 공통 과정**입니다. Pro일 때 달라지는 부분은 각 모듈의 **"⭐ Pro 트랙"** 상자에만 있습니다.
- **모듈 11(Claude Code)** 은 Pro면 교육생 실습, 무료면 강사(Pro) 시연입니다.
- 강사 계정은 **어느 경우든 Pro**를 권합니다 (모듈 11 시연, 사용량 여유).

| 모듈 | 무료 트랙 | ⭐ Pro 트랙에서 달라지는 점 |
|---|---|---|
| 02 가입 | 무료 가입 | 기관이 구독을 준비했다면 가입 후 **Pro 활성화 확인** |
| 03 프로젝트 | 개수 제한 안에서 실습 | 프로젝트를 넉넉히 만들어 업무별로 나눠 보기 |
| 05 스킬 | 같은 SKILL.md를 프로젝트 지침에 붙여넣거나 파일로 첨부 | 스킬로 **등록**해 어느 대화에서든 한 문장으로 사용 |
| 07 프로토타입 | 사용량 한도에 걸리면 ChatGPT와 번갈아 | 수정 요청을 여러 번 해도 여유 |
| 09 배포 | 손으로 커밋·배포 (그대로) | 6단계 "수정 → 재배포"를 Claude Code로 한 번 더 해 보기 (선택) |
| 10 Firebase | 코드를 복사해 붙여넣기 | 5~6단계를 Claude Code에 맡기기 (선택) |
| 11 Claude Code | **강사 시연** + 교육생은 변경 내용 검토 | **교육생 실습** |

> 🧑‍🏫 Pro여도 모듈 09은 **손으로 먼저** 합니다. 손으로 커밋·배포를 해 봐야 모듈 11에서 AI가 대신할 때 무슨 일이 일어나는지 이해합니다.
> 기관 예산으로 해외 구독 서비스를 결제할 수 있는지, 계정을 개인 명의로 할지 기관 명의로 할지는 미리 확인하세요.

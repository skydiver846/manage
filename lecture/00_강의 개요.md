# 생성형 AI 업무 활용 입문 — 강의 개요

> 대상: 컴퓨터는 쓰지만 AI 도구·옵시디언·GitHub 계정이 **하나도 없는** 처음 시작하는 분
> 환경: Windows + Chrome 브라우저
> 진행 방식: 강사가 단계마다 **확인 질문(인터뷰)** 을 던지고, 모두 "완료"하면 다음 단계로

---

## 강의 목표

수업이 끝나면 교육생은 다음을 **혼자서** 할 수 있습니다.

1. 업무용 Google 계정을 만들고 Chrome "업무" 프로필 창에서 쓴다
2. ChatGPT와 Claude에 가입하고, 좋은 프롬프트로 원하는 답을 얻는다
3. AI에 **파일을 건네고**, **프로젝트(폴더)** 로 자료를 묶어 반복 작업을 줄인다
4. 옵시디언에서 MD 파일로 **PRD(기획서)** 를 쓴다
5. 자주 하는 일의 방법을 MD 파일(**SKILL.md**)로 적어 **스킬**로 AI에게 맡긴다
6. 그 PRD를 Gemini Notebook·Claude에 넣어 **요약, 발표자료, 오디오 해설, 프로토타입**을 만든다

## 실습 주제: 과정별 강의평가 결과보고

모든 모듈이 **하나의 행정 업무**를 처음부터 끝까지 자동화하는 흐름으로 이어집니다. 과정이 끝날 때마다 네이버 폼 결과를 엑셀로 내려받아 과목·교관별 평균을 다시 내고, 결과보고서를 쓰는 일입니다.

| 단계 | 지금 (손으로) | 이 강의에서 (AI와 함께) | 모듈 |
|---|---|---|---|
| 참여 요청 | 안내문 직접 작성 | 5요소 프롬프트로 안내문 | 03 |
| 자유의견 정리 | 폼 결과 엑셀의 서술형 칸을 한 줄씩 읽고 요약 | 파일을 건네 과목별 요약 | 03 · 07 |
| 집계 도구 기획 | 없음 | PRD 작성, AI가 구멍(교관 구분) 찾기 | 03 · 05 |
| 결과보고서 | 매 기수 같은 양식을 새로 | 스킬(`eval-report`)로 양식 고정 | 06 · 07 |
| 보고 자료 | 직접 PPT 제작 | Gemini Notebook 슬라이드·인포그래픽 | 07 |
| 집계 | 폼 결과를 엑셀로 내려받아 과목·교관별 평균 계산 (반나절) | 평가 화면이 자동 집계, 3.5 미만 "개선 필요" | 07 · 09 |
| 응답 현황 확인 | 매일 폼 결과 화면 열어 보기 | **코딩 없이** AI 브라우저(Aside) 루틴이 매일 확인 | 08 |
| 응답 모으기 | 네이버 폼 (모으기만, 집계는 따로) | 직접 만든 화면을 웹 주소로 공개(배포). 한곳에 모으는 **공용 장부는 개념만** | 10 |
| 내 업무 도구 | 없음 | 05에서 쓴 **내 PRD**(또는 공공데이터 CSV)로 Claude Code가 화면을 만들고 배포 | 12 |

> 🧑‍🏫 교육생 각자의 업무로 바꿔 보는 연습은 모듈 5의 "내 PRD 쓰기"에서 합니다. 예시 주제를 따라가며 방법을 익히고, 같은 방법을 내 업무에 적용합니다.

## 운영 방식: 4주, 주 1회 (Team 한 달 구독을 최대한 활용)

Claude Team은 **좌석당 한 달 단위**로 결제합니다. 3회를 연달아 하면 구독 기간의 대부분이 비게 되므로, **한 달 안에 주 1회씩** 나눠 진행하고 회차 사이 일주일을 **실제 업무에 써 보는 과제** 기간으로 씁니다. 과제는 [[회차별 과제]] 에 있습니다.

| 주차 | 내용 | 회차 사이 과제 | 주로 쓰는 유료 기능 |
|---|---|---|---|
| D-7 | 구독 시작 → 초대 → 사전 과제 | Claude로 업무 질문 3개 해 보기 | Team 계정 익히기 |
| 1주차 | **1회차** (1~4교시): 03 · 04 · 05 | ① 내 PRD 완성 + 내 업무 프로젝트 일주일 써 보기 | 프로젝트, 팀 공유 프로젝트, 상위 모델 |
| 2주차 | **2회차** (5~8교시): 06 · 07 · 08 · 09 | ② 내 스킬을 실제 업무에 3번 쓰기 + GitHub 가입 | 스킬 등록, 조직 배포 스킬 |
| 3주차 | **3회차** (9~12교시): 10 · 12 · 공유·평가 | ③ 내 화면 한 번 더 고치기 + 동료에게 써 보게 하기 | Claude Code |
| 4주차 | **성과 공유** (1시간, 선택) | - | 좋은 스킬은 조직 배포 후보로 |
| 구독 종료 전 | 연장 여부 결정 | - | 관리자 화면의 사용 분석 참고 |

> 🧑‍🏫 회차 간격이 벌어지므로 각 회차 첫 10분은 **과제 확인 + 복습**으로 고정합니다. 4주차 성과 공유를 따로 잡기 어려우면 3회차 마무리에서 과제 ③을 안내하고, 결과는 팀 공유 프로젝트에 올려 모읍니다. 성과 공유 발표 내용은 과정 결과 보고의 근거 자료로 씁니다.

### 1기 피드백 수집 (2기 설계용)

1기는 2기 커리큘럼을 정하기 위한 **시범 기수**입니다. 아래 세 가지를 꼭 모읍니다.

| 언제 | 무엇을 | 방법 |
|---|---|---|
| 회차가 끝날 때마다 (2분) | **출구 카드**: ① 오늘 가장 쓸모 있던 것 ② 가장 어려웠던 것 ③ 시간이 모자랐던/남았던 교시 | 네이버 폼 3문항 (휴대폰 QR) |
| 12교시 과정 평가 (10분) | 교시별 **유용도·난이도·시간 적정성**(각 1~5점), 빼도 될 것, 더 배우고 싶은 것, 강사·자료 의견 | 네이버 폼 |
| 4주차 성과 공유 | 한 달 동안 실제로 **계속 쓴 기능**과 **줄인 일** | 발표 내용 기록, Team 관리자 화면의 사용 분석 |

> 🧑‍🏫 문항은 [[1기 피드백 문항]] 에 네이버 폼에 붙여넣을 수 있게 정리해 두었습니다. 강사도 회차마다 **실제 걸린 시간**과 막힌 지점을 기록해 두세요. 교시별 유용도가 낮고 난이도가 높은 교시(예: 09 화면 구조, 10 배포)는 2기에서 줄이거나 선택 과정으로 돌릴 후보이고, 유용도가 높은 교시(예: 05 PRD, 06 스킬, 12 내 화면)는 늘릴 후보입니다.

> 🧑‍🏫 시간 조절
> - **사전 과제가 가장 중요합니다.** 계정이 안 된 교육생이 3명만 넘어도 1회차가 30분 이상 밀립니다. 수업 일주일 전에 [[01_구글 업무 계정 만들기]] 와 [[02_ChatGPT와 Claude 가입]] 링크를 보내고, 전날 한 번 더 확인하세요.
> - 회차마다 끝에 과제를 두어 다음 회차 첫 10분에 확인합니다. 과제를 못 해 온 교육생은 예시 PRD로 따라오면 됩니다.
> - 3회차가 밀리면 12의 6단계(한 번 더 고치기)를 빼고 공유 시간을 줄입니다. 과정 평가 10분은 줄이지 마세요(2기 설계 자료). 10은 줄이지 마세요. 교육생이 **직접 만든 화면이 휴대폰에서 열리는 순간**이 과정의 가장 큰 성취입니다.
> - 05의 내 PRD를 못 쓴 교육생은 12에서 05의 "실습 주제 예시" 중 하나를 골라 몇 줄짜리 PRD로 시작합니다.
> - **2일(8시간)로 줄여야 할 때**: 03 자유의견 요약·04 일부·07의 결재 보고서를 빼고, 09는 35분으로, 08·12는 모두 시연(합계 50분)으로 바꿉니다.

### 화면 배치: 강의장 PC는 강사 화면, 노트북은 프로젝터

| 기기 | 역할 | 띄울 것 | 로그인 |
|---|---|---|---|
| **강의장 PC (행정망, 전자교탁)** | 강사가 혼자 보는 화면 | 강사용 열람 페이지, 리허설·수업 기록 페이지 | 강사 개인 Claude |
| **강사 노트북** | **프로젝터로 보여 주는 화면** | 교육생 사이트, Team 계정 Claude, Aside 등 시연 | Team 계정 Claude |
| 교육생 PC (행정망) | 교육생 실습 | 교육생 사이트 | 각자 Team 계정 |

> 🧑‍🏫 전자교탁 PC 화면은 보통 프로젝터로 바로 나갑니다. 강사용 페이지에는 강사 노트와 정답이 있으므로 **수업 전에 프로젝터 입력을 노트북으로 바꾸고, 강의장 PC 화면이 나가지 않는지** 반드시 확인하세요. 노트북은 행정망이 아니라서 노트북에서 되는 것이 교육생 PC에서 막힐 수 있습니다. 교육생이 막히면 강의장 PC(행정망)에서 같은 화면을 열어 확인합니다.

**회차마다 수업 전 점검 (30분 전)**

```
□ 프로젝터 입력을 노트북(HDMI)으로 전환, 강의장 PC 화면이 나가지 않는지 확인
□ 노트북 연결 단자(HDMI · USB-C 젠더)와 전원
□ 노트북 인터넷 (기관 와이파이, 예비로 휴대폰 핫스팟)
□ 노트북 Claude가 Team 화면인지(왼쪽 아래 Team 이름), 크롬 확대 125~150%
□ 강의장 PC에 강사용 열람 페이지와 기록 페이지 열기
□ 교육생 PC 한 대에서 접속 점검 페이지 확인 (Claude 3개는 주소를 눌러 직접 확인)
□ 그 회차에 설치가 있으면(3교시 옵시디언, 7교시 Aside) 교육생 PC 한 대로 설치되는지 확인
□ 수업 후 강의장 PC에서 개인 Claude 로그아웃, 크롬 프로필 정리
```

## 교육생용 강의 사이트

교육생 PC에는 **교육생용 강의 사이트**를 띄워 진행합니다. 강의 플랫폼에는 이 사이트 주소 하나만 링크합니다.

- 만드는 곳: `tools/classroom` (이 강의자료로 자동 생성) → 결과물 `classroom-site/`
- 배포: GitHub `skydiver846/fire-ai-classroom` 저장소의 `fire-ai/` 폴더 → Vercel. 교육생 주소는 `https://www.jg-sobang.com/fire-ai/` (방법은 `tools/classroom/README.md`)
- 교육생판에는 강사 노트·정답·강사용 파일이 빠지고, 사이트 주소는 클릭 링크로, 프롬프트에는 [복사] 버튼이, 모듈마다 실습 파일 [내려받기] 버튼이 붙습니다.
- 강의자료를 고치면 `npm run build` 로 다시 만들어 저장소에 다시 올립니다.

## 자료 배포: 데스크톱이므로 QR보다 링크

QR은 휴대폰 카메라로 찍는 것이라 **데스크톱 PC로는 자료를 받을 수 없습니다.**

| 용도 | 방법 |
|---|---|
| 강의자료·실습 파일 배포 | **짧은 주소를 화면에 띄워 직접 입력**하거나, PC 메신저·메일로 **링크 공유**. 인터넷이 불안하면 실습 파일을 강의장 PC 바탕화면에 미리 복사 |
| 배포한 강의평가 화면에서 평가해 보기 (모듈 10·12) | **QR 사용**: 교육생 본인 휴대폰(LTE)으로 열어 보기 |

# 모듈 5. PRD 작성하기

**이번 시간 목표: 내가 쓰고 싶은 도구의 기획서(PRD) 한 장.** 오늘 저녁 07에서 **화면 시안**이 되고, 내일 12에서 **휴대폰으로 여는 진짜 화면**이 됩니다.

> 🧑‍🏫 강사 시연(30초): 모듈 9 실습 파일의 **일정 플래너 완성 예시**와 **여행 준비물 화면**을 앞 화면에 띄워 눌러 보이며 "이번 과정이 끝나면 이런 나만의 화면을 만듭니다"라고 말합니다. 교육생이 직접 파일을 열게 하지 않습니다.

## 5-0. 맛보기: 한 줄로 시키면? (3분)

Claude 새 대화에 **딱 한 줄만** 넣어 봅니다.

```
여행 준비물 앱 만들어 줘
```

나온 화면을 보고 확인합니다.

- [ ] 할머니 것·아이 것이 **나뉘어** 있나요?
- [ ] **덜 챙긴 사람**이 눈에 띄나요?
- [ ] 새로고침해도 **체크가 남나요?**

대부분 하나 이상 비어 있습니다. AI는 모르는 것을 **마음대로 상상해서** 채웠기 때문입니다.

3-1에서 글은 6하원칙 몇 줄로 충분했습니다. 하지만 **화면(프로그램)은 정할 것이 훨씬 많습니다.** 누가 쓰는지, 어떤 기능이 꼭 필요한지, 무엇은 만들지 않을지. 이것을 **한 장에 정리한 것이 PRD**입니다.

> 🧑‍🏫 세 칸은 5-1에서 예시 PRD를 띄울 때 다시 짚습니다. 예시 PRD에는 "누구 것"(4번 기능), "가족별 서둘러요"·"새로고침해도 남음"(7번 성공 기준)이 모두 적혀 있습니다. **적어 두었기 때문에** 07 화면 시안에서 그대로 나옵니다.

## PRD란?

**PRD (Product Requirements Document, 제품 요구사항 문서)**
= "**무엇을, 누구를 위해, 왜, 어디까지** 만들 것인가"를 한 장에 정리한 기획서

> 비유: 집을 짓기 전 **설계 요청서**. 목수(개발자, 또는 AI)가 이것만 보고도 무엇을 지을지 알 수 있어야 합니다.

### 왜 AI 시대에 PRD가 중요한가?

```그림
 "여행 준비물 앱 만들어 줘"     →  AI가 마음대로 상상해서 만듦  →  내 의도와 다름
 PRD.md 를 첨부하고 "만들어 줘"  →  AI가 요구사항대로 만듦       →  한 번에 가까운 결과
```

PRD는 **한 번 잘 써 두면 여러 도구에 재사용**됩니다.
- Gemini Notebook → 요약, 오디오 해설, 발표 개요
- Claude → 보고서, 안내문, 프로토타입(웹 화면)

---

> 💡 **MD 파일이 뭔가요?** 제목·목록 같은 구조를 `#`, `-` 같은 간단한 기호로 적은 글 파일(`.md`)입니다. 사람도 읽기 쉽고 **AI가 가장 잘 읽는** 형식이라, PRD와 스킬을 이 형식으로 주고받습니다. 메모장으로도 열 수 있습니다.

## 5-1. PRD의 7가지 구성 (7분)

| # | 항목 | 들어갈 내용 | 질문 |
|---|---|---|---|
| 1 | **배경·문제** | 지금 무엇이 불편한가 | 왜 만드나? |
| 2 | **목표** | 성공하면 무엇이 달라지나 (가능하면 숫자) | 무엇을 이루나? |
| 3 | **사용자** | 누가 쓰나, 어떤 상황에서 | 누구를 위해? |
| 4 | **핵심 기능** | 꼭 있어야 할 기능 (우선순위) | 무엇을 하나? |
| 5 | **화면·흐름** | 사용 순서, 화면 구성 | 어떻게 쓰나? |
| 6 | **범위 밖** | 이번에 **안** 하는 것 | 어디까지? |
| 7 | **성공 기준** | 완성 여부를 판단할 체크리스트 | 다 됐는지 어떻게 아나? |

> 💡 **6번 "범위 밖"이 가장 중요합니다.** 이것이 없으면 AI도 사람도 일을 끝없이 키웁니다.

> 🧑‍🏫 표를 짚으면서 예시 [[실습자료/PRD_경주 여행 준비물]] 을 화면에 잠깐 띄워 6번·7번만 보여 줍니다. 강사 멘트: "**안 할 일을 정하는 것이 기획의 절반**입니다. 범위 밖이 없으면 '로그인도, 사진 첨부도, 알림도…' 하다가 끝이 안 납니다. 사람도 AI도요." 맛보기의 세 칸(누구 것, 덜 챙긴 사람, 새로고침)이 4번 기능과 7번 성공 기준에 적혀 있는 것도 가리킵니다.

## 5-3. 내 PRD 쓰기 — AI와 함께 (인터뷰 방식, 40분)

빈 양식을 혼자 채우기 어렵다면 **AI가 나를 인터뷰하게** 합니다.

1. Claude 새 대화에 **인터뷰 프롬프트**를 붙여넣습니다. 아래 [바로 해 보기]에서 예시를 고르거나 칸을 내 말로 바꾼 뒤 **[프롬프트 복사]** 합니다.

<div class="lab" data-lab="fill" data-tpl="prd-interview"></div>

   칸 채우기가 낯설면 아래 **원본**을 복사해 `[내가 만들고 싶은 것]` 자리만 바꿔도 됩니다 ([[실습자료/프롬프트 모음]] 과 같음).

```
너는 경험 많은 기획자야. 나는 "[내가 만들고 싶은 것]"을 기획하려고 해.
PRD를 쓰기 위해 나를 인터뷰해 줘.
- 한 번에 질문 1~2개만 해.
- 배경·목표·사용자·핵심 기능·화면 흐름·범위 밖·성공 기준 순서로 물어봐.
- 내가 다 답하면 Markdown 형식의 PRD 한 장으로 정리해 줘.
- 내가 말하지 않은 내용은 [확인 필요]로 표시해.
```

> 💡 이 프롬프트를 기억해 두세요. 기획할 때마다 이 긴 글을 다시 찾아 붙여넣어야 합니다. 다음 모듈(스킬)에서 이것을 **한 문장**으로 줄입니다.

2. AI 질문에 답하기 → 마지막에 이어서 입력: `이 PRD를 "PRD_내 도구.md" 파일로 내려받게 해 줘` → 내려받은 파일을 내 업무 폴더 `01_기획(PRD)` 에 옮기기
3. **[확인 필요]** 부분을 직접 채우고(**Ctrl + F** 로 검색), 틀린 내용을 고칩니다. **최종 책임자는 나**입니다.

> 🧑‍🏫 강사 팁
> - AI의 첫 질문은 보통 "지금은 어떻게 관리하나요? 가장 불편한 점은?"입니다. **말하듯 편하게** 답하게 하세요. 정리는 AI가 합니다.
> - 답변에 실명·연락처 같은 **개인정보**를 넣지 않게 다시 짚어 주세요.
> - 시간이 부족하면 **4교시 처음 10분**을 PRD 마무리에 더 씁니다(06이 40분이면 끝남). 그래도 덜 됐으면 질문 3~4개 후 "지금까지 내용으로 PRD를 정리해 줘"로 끊고, 나머지는 2일차 8교시 시작 때 PRD 반영 5분에 함께 채웁니다. 5교시 내 화면 시안은 정리된 만큼으로 만들어도 됩니다.

### 주제 고르는 기준 (2일차까지 이어 씁니다)

여기서 쓰는 **내 PRD**는 06 스킬, 07 화면 시안을 거쳐 2일차 모듈 12에서 **내 화면**으로 만들어집니다. 그래서 주제를 처음에 잘 고르는 것이 중요합니다.

**1. 업무든 일상이든 "내가 정말 쓰고 싶은 것"을 고릅니다.** 평소 "AI로 도움받고 싶었던 일"도 좋고, 집에서 매번 손으로 정리하던 일도 좋습니다. 내가 쓰고 싶어야 2일차까지 끝까지 만듭니다.

**2. 크기는 "화면 1장, 핵심 기능 3개"까지.** 2일차에 한 시간 안에 만들 수 있는 크기입니다.

| 좋은 주제 | 피할 주제 |
|---|---|
| 자주 반복하는 일 (매주·매달 손으로 다시 정리하는 것) | 화면 여러 장, 로그인, 결재·승인 흐름 |
| 입력 → 계산·정리 → 결과 보기로 끝나는 일 | 여러 사람의 입력을 한곳에 모아야만 쓸모 있는 일 (수업 화면은 **내 브라우저에만** 저장) |
| 가짜 예시 데이터로도 연습할 수 있는 일 | 실명·연락처·내부 기밀이 꼭 들어가야 하는 일, 기관 전산시스템과 연결해야 하는 일 |

**3. 일상 주제도 배우는 방법은 같습니다**(모으기 → 정리·계산 → 결과 보기). 같은 모양의 일이면 나중에 업무로 그대로 옮길 수 있습니다.

| 일상 주제 예시 | 같은 모양의 업무 |
|---|---|
| 동호회 회비·출석 관리 | 교육생 출결, 강사료 정리 |
| 운동·독서 기록과 월별 통계 | 교육 실적 월별 집계 |
| 가족 여행 일정·준비물 체크 | 과정 운영 일정, 점검 체크리스트 |
| 텃밭·캠핑 장비 대장 | 교육 장비 대여·반납 대장 |

일상 주제로 한 사람은 마지막 10교시 업무 적용 계획에 **"이 방법을 내 업무 어디에 쓸지" 한 줄**을 꼭 적습니다.

### 실습 주제 예시 (일상과 업무 섞어서)

| 일상 | 업무 |
|---|---|
| 우리 집 가계부 (항목별 지출 합계) | 부서 행사 준비 체크리스트 |
| 아이 학원 일정 한눈에 보기 | 교육 일정 안내 화면 |
| 운동 기록과 주간 통계 | 교육 장비 대여·반납 대장 |
| 주간 식단표 | 교육생 출결·외출 관리 화면 |

## 좋은 PRD 체크리스트

```그림
□ 처음 보는 사람이 읽어도 무엇을 만드는지 1분 안에 이해된다
□ 핵심 기능에 우선순위(필수/있으면 좋음)가 있다
□ "범위 밖" 항목이 최소 2개 있다
□ 성공 기준이 체크 가능한 문장이다 ("빠르게" ✗ → "3초 안에" ✓)
□ 개인정보·내부 기밀이 들어 있지 않다
```

> 🪜 **업무 자동화 사다리:** ① 잘 시키기 → ② 자료 맡기기 → ③ 방법 맡기기 → ④ 클릭 맡기기 → **⑤ 내 도구 만들기 ✔** → ⑥ 저절로 돌아가게 (⑤ 내 도구 만들기의 설계도를 그립니다)

> 💼 **업무에서는?** 같은 방법으로 업무 도구 기획서나 전산 개발 요청서를 씁니다. "무엇을, 누구를 위해, 어디까지"와 범위 밖을 적어 건네면 담당자도 AI도 한 번에 알아듣습니다.

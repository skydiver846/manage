10 Firebase 공용 장부

모듈 10 (심화 3). Firebase로 "공용 장부" 연결하기

1단계: Firebase 프로젝트 만들기 (5분)

  1. 업무 창에서 console.firebase.google.com (Google 서비스라 가입 없음)
  2. [프로젝트 만들기] → 이름 attendance-12 → 약관 동의 → [계속]
  3. AI 도우미(Gemini) 질문이 나오면 원하는 대로 (사용 안 함도 가능)
  4. Google 애널리틱스: 사용 안 함 → [프로젝트 만들기] → 1분 대기 → [계속]
  5. ✅ 왼쪽 위에 attendance-12, 가운데에 iOS·Android·</> 아이콘이 보이면 완료

2단계: 공용 장부(Firestore) 만들기 (5분)

  1. 왼쪽 메뉴 빌드(Build) → Firestore Database → [데이터베이스 만들기]
  2. 에디션 선택이 나오면 Standard
  3. 위치: asia-northeast3 (서울) → ⚠️ 나중에 바꿀 수 없습니다
  4. 프로덕션 모드로 시작 → [만들기]

3단계: 장부 사용 규칙 정하기 (10분)

Firestore 화면 위쪽 규칙(Rules) 탭 → 내용을 모두 지우고 아래를 붙여넣기 → [게시(Publish)]

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /attendance/{recordId} {
      // 명단은 누구나 볼 수 있다
      allow read: if true;
      // 새 출석은 정해진 칸만, 정해진 모양으로 쓸 수 있다
      allow create: if request.resource.data.keys().hasOnly(['name', 'no', 'date', 'time'])
        && request.resource.data.keys().hasAll(['name', 'no', 'date', 'time'])
        && request.resource.data.name is string
        && request.resource.data.name.size() > 0
        && request.resource.data.name.size() <= 20
        && request.resource.data.no is string
        && request.resource.data.no.matches('^[0-9]{2}$');
      // 한번 쓴 출석은 고치거나 지울 수 없다
      allow update, delete: if false;
    }
  }
}

4단계: 출석부와 장부를 잇는 설정값 받기 (5분)

  1. 왼쪽 위 프로젝트 개요 → 가운데 </> (웹) 아이콘
  2. 앱 닉네임 출석부 → Firebase Hosting 체크하지 않기 (배포는 Vercel이 함) → [앱 등록]
  3. 화면에 나오는 코드 중 const firebaseConfig = { ... }; 부분만 복사 → 옵시디언 02_참고자료 에 Firebase 설정값 노트로 저장
  4. [콘솔로 이동]
const firebaseConfig = {
  apiKey: "AIza…",
  authDomain: "attendance-12-a1b2c.firebaseapp.com",
  projectId: "attendance-12-a1b2c",
  …
};

5단계: PRD 고치기 → Claude로 코드 고치기 (15분)

① PRD를 먼저 고칩니다 (기준 문서는 언제나 PRD). 옵시디언에서 PRD를 v0.4 로:

  • 6번 범위 밖에서 "여러 기기 간 데이터 공유"를 삭제 → 이제 범위 안
  • 4번 핵심 기능에 "모든 기기에서 같은 명단을 실시간으로 본다" 추가
  • 삭제(×)와 전체 초기화는 범위 밖으로 이동 (장부 규칙상 지울 수 없음, 관리자 기능은 다음 단계)

② Claude 새 채팅에 PRD v0.4 + 현재 index.html 두 파일을 첨부하고:

첨부한 index.html은 출석 기록을 브라우저(localStorage)에 저장하는 출석부야.
첨부한 PRD v0.4에 맞게, 기록을 Firebase Firestore에 저장하도록 고쳐 줘.

- 내 Firebase 설정값은 아래와 같아:
  (여기에 firebaseConfig 붙여넣기)
- HTML 파일 하나로 유지하고, Firebase는 공식 CDN(gstatic.com)의 모듈 방식으로 불러와 줘
- 컬렉션 이름은 attendance, 필드는 name, no, date(YYYY-MM-DD), time(HH:MM)만 써 줘
- 문서 ID는 "날짜_번호_이름"으로 정하고, 같은 문서가 이미 있으면 "이미 출석했습니다"를 보여 줘
- 오늘 날짜 기록만 실시간으로 보여 줘 (정렬은 화면에서 해 줘)
- 삭제 버튼과 전체 초기화는 없애 줘
- 나머지 화면 디자인과 정시/지각 판정은 그대로 둬

③ 내 컴퓨터에서 먼저 확인: Claude 결과를 메모장에 index.html(UTF-8)로 저장 → 더블클릭 → 출석 체크 → Firebase 콘솔 Firestore → 데이터 탭에 attendance 아래 기록이 생기면 성공

6단계: GitHub에 커밋 → 자동 배포 (5분)

  1. GitHub attendance-prototype → index.html → 연필(✏️)
  2. 기존 내용을 Ctrl + A 로 모두 선택 → 새 코드로 붙여넣기
  3. [Commit changes…] → 메시지 출석 기록을 Firebase 공용 장부에 저장 → [Commit changes]
  4. Vercel Deployments 에서 Ready 확인 (주소는 그대로)

⭐ Pro 트랙 (선택): 5~6단계를 Claude Code에 맡길 수 있습니다. 저장소를 연결하고 "PRD v0.4에 맞게 index.html을 Firestore에 저장하도록 고치고 커밋해 줘"(5단계 지시문 그대로)라고 지시하면, 복사·붙여넣기 없이 커밋까지 됩니다. 단, Firebase 설정값과 보안 규칙은 사람이 직접 확인합니다. 방법은 모듈 11 참고.

7단계: 짝꿍과 같은 명단 확인 (5분)

  1. 짝꿍과 같은 출석부 주소(한 사람의 Domains 주소 QR)를 각자 휴대폰으로 열기
  2. 한 사람이 출석 → 다른 사람 화면에 새로고침 없이 이름이 나타나는지 확인
  3. 같은 이름 + 같은 번호로 다시 출석 → "이미 출석했습니다"
  4. 강사 PC에서 Firebase 콘솔 데이터 탭을 띄워 기록이 쌓이는 모습 보여 주기

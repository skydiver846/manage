# 프롬프트 모음 (수업 중 복사해서 사용)

← [[00_강의 개요]]

## 기본 공식

```
[역할] 너는 ___야.
[목표] ___을 해 줘.
[맥락] 배경은 ___.
[형식] ___ 모양으로 (분량: ___).
[조건] ___은 지키고, 모르는 내용은 [확인 필요]로 표시해.
```

## 손 풀기 (모듈 2)

```
안녕! 나는 오늘 처음 생성형 AI를 써 보는 사람이야.
너는 무엇을 잘하고, 무엇을 조심해서 써야 하는지 초등학생도 알 수 있게 5줄로 알려줘.
```

## 되묻기 (모듈 3)

```
이 작업을 잘하기 위해 내가 빠뜨린 정보가 있으면, 답하기 전에 먼저 질문해 줘.
```

## 좋은 지시 예시: 오리엔테이션 안내문 (모듈 3)

```
[역할] 너는 소방학교 교육운영 담당자야.
[목표] 신임소방관 교육생에게 보낼 첫날 오리엔테이션 안내문을 써 줘.
[맥락] 교육생 40명, 3주 과정, 첫날 09:00 본관 강당 집합, 개인 체력복 지참.
[형식] 제목 1줄, 인사말 2줄, 핵심 안내 5개 항목(글머리표), 준비물은 표로.
[조건] 정중한 존댓말, A4 반 장 이내, 확인되지 않은 내용은 [확인 필요]로 표시.
```

## 첨삭 예시: 장비 점검 보고 메일 (모듈 3)

```
[역할] 너는 ○○119안전센터 장비 담당자야. 센터장님께 보고 메일을 쓰는 상황이야.
[목표] 이번 달 장비 점검 결과를 보고하고, 불량 장비 교체 예산을 요청하는 메일을 써 줘.
[맥락] 10월 1~2일 공기호흡기 12대 점검. 정상 10대, 2대는 압력 게이지 불량으로 사용 중지함.
[형식] 메일 제목 1줄, 본문 3문단(결과 요약 / 불량 내용 / 요청 사항), 점검 결과는 표로.
[조건] 정중한 존댓말. 예산 금액이나 교체 일정처럼 내가 주지 않은 정보는 [확인 필요]로 표시해.
```

## 파일 요약 (모듈 3)

```
첨부한 문서를 읽고
1) 핵심 내용 3줄 요약
2) 실제로 해야 할 일(To-do) 목록
3) 문서에서 모호하거나 빠진 부분
을 표로 정리해 줘. 문서에 없는 내용은 지어내지 마.
```

## 프로젝트 지침 (모듈 3)

```
너는 소방학교 교육운영 담당자를 돕는 보조자야.
- 항상 정중한 존댓말로 답한다.
- 프로젝트에 올린 파일 내용을 우선 근거로 삼고, 파일에 없는 내용은 [확인 필요]로 표시한다.
- 일정·인원·준비물은 표로 정리한다.
- 답 끝에 "다음에 할 일" 1~3개를 제안한다.
```

## 스킬 만들어 달라고 하기 (모듈 5)

```
우리 기관의 결재 보고서 양식(제목 / 추진 배경 / 주요 내용 / 기대 효과 / 향후 일정 표)으로
보고서를 써 주는 스킬을 만들어 줘.
- name은 report-format, SKILL.md 하나로
- description에 "언제 쓰는지"를 꼭 넣어 줘
- 자료에 없는 숫자는 [확인 필요]로 표시하게 해 줘
```

> 스킬 파일 예시: [[실습자료/스킬/prd-interview/SKILL]]

## PRD 인터뷰 (모듈 6, 스킬이 없을 때)

```
너는 경험 많은 기획자야. 나는 "[내가 만들고 싶은 것]"을 기획하려고 해.
PRD를 쓰기 위해 나를 인터뷰해 줘.
- 한 번에 질문 1~2개만 해.
- 배경·목표·사용자·핵심 기능·화면 흐름·범위 밖·성공 기준 순서로 물어봐.
- 내가 다 답하면 Markdown 형식의 PRD 한 장으로 정리해 줘.
- 내가 말하지 않은 내용은 [확인 필요]로 표시해.
```

## PRD 검토 (모듈 7, NotebookLM)

```
이 PRD에서 "범위 밖"으로 정한 것과, 성공 기준을 표로 정리해 줘.
그리고 PRD 안에서 서로 모순되거나 빠진 부분이 있으면 알려 줘.
```

## 결재 보고서 (모듈 7, ChatGPT)

```
첨부한 PRD를 바탕으로 상급자 결재용 1페이지 보고서를 써 줘.
형식: 제목 / 추진 배경 / 주요 내용 / 기대 효과 / 향후 일정(표).
PRD에 없는 숫자는 만들지 말고 [확인 필요]로 표시해.
```

## 발표 개요 (모듈 7, ChatGPT)

```
이 PRD로 10분 발표를 하려고 해. 슬라이드 7장 구성으로
장마다 제목, 핵심 문장 1개, 들어갈 그림 아이디어를 표로 정리해 줘.
```

## 프로토타입 (모듈 7, Claude)

```
첨부한 PRD를 읽고, 핵심 기능(필수)만 동작하는 프로토타입 웹 화면을 만들어 줘.
- HTML 파일 하나로, 설치 없이 브라우저에서 바로 열리게
- 휴대폰 화면에서도 보기 좋게
- "범위 밖" 기능은 넣지 마
- 처음 열었을 때 예시 데이터 3개를 보여 줘
```

## 코드 한 줄씩 설명받기 (모듈 8)

```
첨부한 3-js.html을 코딩을 처음 보는 사람에게 설명해 줘.
<script> 부분을 한 줄씩, 비유를 들어서 설명하고
PRD의 어느 규칙과 연결되는지도 표로 정리해 줘.
```

## 기능 추가 요청하기 (모듈 8)

```
첨부한 3-js.html에 "같은 이름과 번호로 다시 출석하면 막기"를 추가해 줘.
바꾼 줄에는 주석으로 표시해 줘.
```

## Firebase 공용 장부로 바꾸기 (모듈 10)

```
첨부한 index.html은 출석 기록을 브라우저(localStorage)에 저장하는 출석부야.
첨부한 PRD v0.4에 맞게, 기록을 Firebase Firestore에 저장하도록 고쳐 줘.

- 내 Firebase 설정값은 아래와 같아:
  (여기에 firebaseConfig 붙여넣기)
- HTML 파일 하나로 유지하고, Firebase는 공식 CDN(gstatic.com)의 모듈 방식으로 불러와 줘
- 컬렉션 이름은 attendance, 필드는 name, no, date(YYYY-MM-DD), time(HH:MM)만 써 줘
- 문서 ID는 "날짜_번호_이름"으로 정하고, 같은 문서가 이미 있으면 "이미 출석했습니다"를 보여 줘
- 오늘 날짜 기록만 실시간으로 보여 줘 (정렬은 화면에서 해 줘)
- 삭제 버튼과 전체 초기화는 없애 줘
- 나머지 화면 디자인과 정시/지각 판정은 그대로 둬
```
